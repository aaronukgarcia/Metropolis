# Acceptance criteria — engine.news (MOD-043)

**BOW code:** MOD-043
**Spec refs:** §29 The News System (`docs/METROPOLIS-MASTER-v2.1.md` lines 426-433: four layers — Ticker (atomic events), Monthly Bulletin ("front page at month-end: 3–5 ranked stories, editor = salience scoring: deaths, firsts, records, crises, milestones"), Annual Review ("year in numbers + biggest story"), Epilogue ("the city's whole history at win/death"); "LLM soft-layer (optional, online): rewrites bulletin prose with flavour; the *facts* always come from the engine — no hallucinated news."); §20 Roads & Auto-Naming (lines 360-370: deterministic real-name generation for roads/civic buildings/citizens, "The ticker uses names, so the city reads like a place, not a spreadsheet."); V.1 (line 1300: "News bulletin/ticker/annual/epilogue → §29"; line 1323: LLM soft-layer explicitly listed as "optional online feature, post-v1" among out-of-scope-v1 items — read alongside §29's "optional, online" wording, not contradicting it: the mechanism's contract is specified now, the feature is not required to ship enabled in v1); §3 Time (two-layer clock — monthly tick as the bulletin's natural cadence); code.json `engine.news` entry (inbound `NewsAPI`, format "Go package API + deltas", pattern "event bus consumer; salience scoring; searchable archive", registered consumers `engine.coastal`, `engine.tourism`, `ui.screen.ticker`; outbound calls registered to `engine.core` and `engine.roads` only — see Escalations, this is far short of what §29's event categories require, and is reported against **BUG-058** below, not assumed complete).

## User stories

- **US-1.** As `ui.screen.ticker` (a registered consumer), I need a rolling feed of atomic ticker events, each traceable to the real sim event and named entity (§20) that produced it, so the ticker reads as the city's own record, not generated flavour text.
- **US-2.** As the player reading the monthly bulletin, I need 3-5 ranked stories chosen by a real salience-scoring editor over that month's actual events (deaths, firsts, records, crises, milestones per §29), so the front page reflects what actually happened and its relative importance, not a fixed or arbitrary selection.
- **US-3.** As the player at year-end, I need an annual review (year in numbers + biggest story) drawn from the same underlying event record the bulletin used all year, so the numbers reconcile rather than being a second, independently-computed account that can drift from what the ticker/bulletin already said.
- **US-4.** As the player reaching a win or death condition, I need an epilogue built from the whole persisted history log, where every claim it makes is traceable to a specific recorded event — because a wrong closing statement is, per this project's own framing, the most memorable defect the game can ship.
- **US-5.** As GR#3 (single source of truth) and the drill-through rule (UI-SPEC §4: "every number on every screen is selectable and Enter goes to its source"), I need every news item — atomic, bulletin, annual, epilogue — to carry a reference back to the sim state/record that produced it, so a player (or a Tester) can always ask "says who" and get a real answer, never a plausible-looking string with nothing behind it.
- **US-6.** As the optional online LLM soft-layer (§29, post-v1 per V.1's scope table), I need my role provably restricted to prose rewriting — the facts I'm handed must reach the player unchanged, and if I alter a fact, the pipeline must catch and reject that, never publish it — so "no hallucinated news" is an enforced property of the pipeline, not a hope about model behaviour.
- **US-7.** As whoever eventually resolves `BUG-058`, I need this file to name exactly which of §29's event categories (deaths, firsts, records, crises, milestones) this module can source for real today versus which have no registered code.json edge yet, so the gap is documented against a specific BOW item rather than silently absorbed into "engine.news works."

## Scope

Four generation layers (ticker, monthly bulletin, annual review, epilogue) over a persisted history/event log; a salience-scoring editor selecting the bulletin's 3-5 stories; a searchable archive; an attributability contract binding every generated news item to the sim record it restates; and the optional LLM rewrite seam with its facts-locked contract (mechanism only — the LLM does not have to be wired to a real API for this item, per V.1's "post-v1" scope note, but the seam and its fact-lock enforcement must exist and be tested against a mocked LLM).

## Acceptance criteria

### Functional

- **AC-1 (GR#20; code.json inbound contract — ticker layer).** A `NewsAPI` (or equivalent) exists matching code.json's registered inbound pattern ("event bus consumer; salience scoring; searchable archive"). Its ticker-ingestion path accepts real sim events and emits ticker items, where every emitted item carries a reference (event ID, entity ID, and sim tick/month) back to the originating record — not free text alone. Check: `go doc ./internal/engine/news NewsAPI` (or equivalent) shows a ticker-item type with a source-reference field; a passing test constructs two ticker items from two different injected sim events and asserts their source references differ and each resolves back to the injected event it came from (`grep -rn "func Test.*[Tt]ickerAttribut\|func Test.*[Ss]ourceRef" internal/engine/news/*_test.go`). **False-pass risk stated:** a ticker item carrying a non-empty string field named something like `Source` that is populated with a hardcoded or cosmetic value (e.g. `"engine"`) would pass a bare existence grep — the check requires the reference to resolve to the specific injected event, proven by varying the input and observing the reference change correspondingly.
- **AC-2 (§29; monthly bulletin, real salience scoring).** A monthly bulletin generator selects 3-5 stories from the month's actual events via a salience-scoring function over the named categories (deaths, firsts, records, crises, milestones), where changing an event's salience-relevant magnitude (e.g. a death count, a record's margin, a crisis's severity) changes its rank in the output. Check: a passing test injects a set of synthetic events including at least two in the same category with different magnitudes, and asserts the higher-magnitude event ranks above the lower one in the bulletin's ordering (`grep -rn "func Test.*[Ss]alience" internal/engine/news/*_test.go`). **False-pass risk stated:** a generator that always returns the first 3-5 events in chronological or insertion order would satisfy "produces 3-5 stories drawn from the month's events" without ever computing salience — this AC's check is specifically that varying magnitude (not just varying which events exist) changes rank, which a chronological-order or fixed-selection implementation cannot produce.
- **AC-3 (§20; named-entity attribution where a name is available).** Where a bulletin/ticker story's category has a real named entity available through a *registered* outbound edge (currently: roads, via `engine.roads`), the generated story text/data uses that entity's actual name from the registry seeding the scenario, not a placeholder or a generated-but-unlinked name. Check: a passing test seeds a scenario with a specific named road (e.g. via `engine.roads`'s naming output) and a congestion event on that road, then asserts the generated story's road-name field equals the seeded road's actual `Name`, not a hardcoded example or independently-generated string (`grep -rn "func Test.*[Rr]oadNam.*[Ss]tory\|func Test.*[Nn]amedAttribut" internal/engine/news/*_test.go`). **False-pass risk stated:** a story template that interpolates *some* string into a `{{roadName}}` slot would pass a grep for "uses a name field" — the check requires the interpolated value to be traced back to the seeded road entity specifically, not merely present.
- **AC-4 (§29; annual review shares the SSOT event log, GR#3).** The annual review ("year in numbers + biggest story") is computed from the same underlying event/history store the bulletin draws from across the year — not a second, independently-accumulated running total that could drift from what the ticker/bulletin already reported. Check: `go doc ./internal/engine/news` shows the annual-review generator's input type is the same event-log/history type the bulletin generator consumes (not a parallel accumulator struct); a passing test asserts a year's bulletin outputs and that year's annual-review "year in numbers" are computed from an identical injected event set and reconcile (e.g. total deaths reported by the annual review equals the sum the bulletin's death-category events would independently total) (`grep -rn "func Test.*[Aa]nnualReconcile\|func Test.*[Ss]ameEventLog" internal/engine/news/*_test.go`).
- **AC-5 (§29; epilogue — the sharpest attributability check, "the most memorable defect the game can have").** The epilogue is generated exclusively from the persisted history log — its generation function's only input is that log (plus static naming/formatting data), with no side-channel access to live engine state that bypasses the log — so it is structurally incapable of asserting a fact the log does not support. Check: `go doc ./internal/engine/news Epilogue` (or equivalent) shows the function signature takes the history log as its data input, not a live engine/world reference; a passing test removes (redacts) a specific milestone record from an otherwise-complete history log and asserts the generated epilogue no longer states that milestone was reached, compared against a control run with the record present (`grep -rn "func Test.*[Ee]pilogueRedact\|func Test.*[Ee]pilogueAttribut" internal/engine/news/*_test.go`). **False-pass risk stated explicitly:** a test that only checks "the epilogue mentions the final population figure" without ever varying the underlying log would pass a stub that fabricates a plausible-looking number from a live counter rather than the log — the check requires demonstrating that redacting the log's record measurably changes the epilogue's output, which a log-independent implementation cannot do.
- **AC-6 (§29; LLM soft-layer is fact-locked, "no hallucinated news").** When the optional LLM rewrite layer is enabled, the pipeline validates that every fact (name, number, date/tick) present in the LLM's rewritten prose matches the pre-computed engine facts exactly; a fact-altering LLM response is detected and rejected (falling back to the un-rewritten engine text, AC-7) rather than published as-is. Check: a passing test feeds a mocked LLM client whose response alters a specific fact (e.g. changes a stated death count or a named entity) and asserts the pipeline's output either matches the original engine facts (rejection occurred) or is flagged/logged as rejected — never silently publishes the altered figure (`grep -rn "func Test.*[Ff]actLock\|func Test.*[Ll][Ll][Mm].*[Rr]eject" internal/engine/news/*_test.go`). **False-pass risk stated explicitly:** an integration test that only checks the LLM code path doesn't error or crash, without ever feeding it a response that alters a fact, would pass a fully-trusting pass-through implementation that publishes whatever the LLM returns — the check requires the injected mock to actively contradict a known fact and requires the test to assert that contradiction did not reach output.
- **AC-7 (LLM soft-layer failure/absence never blocks or drops a story).** If the LLM rewrite call fails, times out, or the soft-layer is disabled (the default/expected v1 state per V.1's "post-v1" scope note), the affected bulletin/epilogue item is still produced using the plain engine-generated prose — never dropped, never blocked pending a retry that could stall the monthly tick. Check: a passing test simulates an LLM call failure (error or timeout from the mocked client) and asserts a complete, fact-correct news item is still emitted (`grep -rn "func Test.*[Ll][Ll][Mm].*[Ff]ail\|func Test.*[Ll][Ll][Mm].*[Ff]allback" internal/engine/news/*_test.go`).

### Error handling

- **AC-8 (GR#7).** A generation-time reference to an entity that no longer resolves in current state (e.g. an event references a citizen/road ID that has since been removed or was never registered) produces a registry-sourced error, never a silently-dropped story or a fabricated placeholder name substituted in its place. Check: `grep -n "MET-" internal/engine/news/*.go` finds a registry code reference (new sub-range, claimed at build time — no range exists yet for `engine.news` in `data/errors.json`, the same situation `engine.season`/`engine.market` were in before their build); passing test coverage (`grep -rn "func Test.*[Uu]nresolvedRef\|func Test.*[Dd]anglingEntity" internal/engine/news/*_test.go`) — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that no fabricated placeholder name or silently-dropped story was created, not merely that a matching-named test function exists.
- **AC-9 (GR#17; unselected is not unrecorded — the archive is the safety net for the editor).** An event considered by the salience-scoring editor but not selected for the bulletin's 3-5 stories remains queryable/attributable in the searchable archive (§29's own "archive searchable" clause) — "didn't make the front page" must be a distinguishable state from "never happened" or "was silently dropped." Check: a passing test injects more candidate events than the bulletin's story slots, and asserts a lower-salience event that didn't make the top selection is still retrievable via the archive's query path (`grep -rn "func Test.*[Aa]rchiveRetain\|func Test.*[Uu]nselectedQueryable" internal/engine/news/*_test.go`). **False-pass risk stated:** a bulletin generator that discards non-selected candidates after ranking (keeping only the winning 3-5 in memory/storage) would still pass any test that only checks the bulletin's own output — the check specifically queries the archive for a non-winning event, which a discard-after-rank implementation cannot satisfy.

### Determinism & safety

- **AC-10 (GR#21).** Given the same underlying event/history log and the same salience-scoring configuration, bulletin/annual-review/epilogue generation is deterministic: repeated runs and different worker counts produce byte-identical selected-story sets and rank order, including a documented, deterministic tie-break rule (e.g. stable ordering by event ID) when two events' salience scores are equal. Check: a passing determinism test includes at least one scenario with two events of deliberately tied salience score and asserts the tie-break order is identical across repeated runs (`grep -rn "func Test.*[Dd]eterminis" internal/engine/news/*_test.go`). **False-pass risk stated explicitly:** a determinism test built only from events with already-distinct salience scores would never exercise the tie-break path and could pass an implementation with map-iteration-order nondeterminism hiding exactly there — the check requires a tied-score case specifically.
- **AC-11 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/engine/news/*.go` (excluding `_test.go`) returns no matches — news generation is a function of the sim event log and month/tick index only, never wall clock.
- **AC-12.** `go test ./internal/engine/news/... -race -count=1` passes with no data race when the ticker's event-ingestion path is fed concurrently from multiple shard workers.

### Documentation

- **AC-13.** `internal/engine/news/doc.go` states the module key `engine.news`, cites §29 and §20, lists all four layers with a one-line description each, states the LLM soft-layer's facts-locked contract (AC-6/AC-7) and its "post-v1, optional" status per V.1, and states explicitly which of §29's five story categories (deaths, firsts, records, crises, milestones) this module can source through a *currently registered* code.json outbound edge versus which cannot yet — see BUG-058 below — so the gap is visible in the code, not only in this file. Check: `grep -n "engine.news" internal/engine/news/doc.go` and `grep -n "§29\|section 29" internal/engine/news/doc.go` both match; `grep -n "BUG-058" internal/engine/news/doc.go` matches.
- **AC-14 (GR#20 enforcement, tied to BUG-058 — a module's own import graph must not exceed its registered edges).** `internal/engine/news`'s Go imports of other `internal/engine/*` packages are a subset of code.json's registered outbound `calls` list for `engine.news` at build time. If a story category needs a module with no registered edge (deaths → citizens/population, financial milestones → finance, crises → crime/health/finance), this package either (a) does not implement that category yet and says so in `doc.go`, or (b) the missing edge is registered first via `master-plan-v2.1.json` + regenerate (never a hand-edit to `code.json`, per BUG-058's own recommendation) before the import is added. Check: `grep -rn "^\s*\"internal/engine/" internal/engine/news/*.go` (excluding `_test.go`) lists every internal/engine import; each must appear in code.json's `engine.news.outbound.calls` at the time of the check — a mismatch is a real GR#20 violation, not a documentation gap. **False-pass risk stated:** a grep that only checks *code.json has some outbound entry* (rather than cross-referencing it against the actual import list) would pass a build that quietly imports `engine.finance` directly with no registered edge at all — the check must diff the two lists, not confirm either exists in isolation.

## Out of scope

- `engine.coastal`'s and `engine.tourism`'s own event-generation logic, and `ui.screen.ticker`'s rendering — this item only needs to expose `NewsAPI` correctly to its three currently-registered consumers; their internals are each module's own item.
- Resolving BUG-058 itself (registering the missing outbound edges for citizens/finance/crime/health-sourced story categories) — that is a `master-plan-v2.1.json` + regenerate task for whoever owns that fix; this item documents the gap (AC-13/AC-14) and refuses to bypass it (AC-14), it does not fix the registry.
- An actual online LLM API integration — the fact-lock seam (AC-6/AC-7) must exist and be tested against a mocked client; wiring a real provider is post-v1 per V.1's own scope table.
- Coastal-arrival-specific news framing (§30's "ticker/bulletin report it factually" instruction) beyond the generic attributability contract this file establishes — the specific neutral-framing language for arrivals stories belongs to `engine.coastal`'s own item, consumed through the registered edge at AC-1/AC-9.
- Any UI presentation beyond `ui.screen.ticker`'s already-registered consumption (bulletin/annual/epilogue screens, if UI-side, belong to the UI-track BAs' files).

## Escalations

- **For Bill — BUG-058-class gap, specific to this module (new finding, report against BUG-058, do not edit code.json).** `engine.news`'s registered outbound `calls` list is `engine.core` and `engine.roads` only. §29 names five story categories — deaths, firsts, records, crises, milestones — of which only "records" involving a named road (AC-3) has a real registered path today. Deaths and firsts plausibly need a citizens/population module edge (no such module is registered as an `engine.news` outbound call at all); milestones plausibly need `engine.finance` and/or `engine.core`'s own milestone-ladder tracking (§4); crises plausibly need `engine.crime`/`engine.health`/`engine.finance` (Detroit-spiral-adjacent, §12). None of these edges exist in code.json for `engine.news` in either direction. This is the exact shape BUG-058 already names ("a developer meeting an unregistered-but-required call has no correct move") and BA-S8a found it independently while reading this module specifically — consistent with BUG-058's own note that "the true extent is unknown and these two are just the ones a human-shaped read happened to reach." Recording this as a third instance for BUG-058's tracking, not a new bug. AC-14 is written so a developer cannot silently resolve this by importing anyway; the correct move is registering the edges via the master plan first.
- **Assumption logged (per BA instructions §3) — ASM-below, salience-scoring weight table.** §29 names the five story categories but gives no relative weighting between them (is one death worth more salience than one "record"? how does a crisis compare to a milestone?). AC-2 requires *some* magnitude-sensitive scoring function exist and is testable, but the actual weight table is left to build time as data (GR#15), not invented here as a specific formula.
- **Assumption logged — ASM-below, fact-lock comparison granularity.** AC-6's "matches exactly" requirement for names/numbers/dates is this BA's own mechanism, not spec text (§29 only says "the facts always come from the engine — no hallucinated news"); the exact-match approach is the most defensible reading but a fuzzy/approximate-match alternative was not chosen, and is flagged in case Bill wants a looser tolerance for, e.g., LLM-paraphrased numbers written in words ("a dozen" vs "12").
- **Assumption logged — ASM-below, archive retention.** §29 says the archive is "searchable" but not for how long or at what volume ceiling, and this project's citizen model is explicitly no-culls-ever at up to 100M (§5) — this file assumes full-history retention with no pruning for the news archive specifically (news text volume is orders of magnitude smaller than raw per-citizen state, so retention risk is low relative to the citizen store, but the assumption is still a real one and not spec-stated).
- **Assumption logged — ASM-1423 (P3, balance placeholder).** The fact-word token list in `news-facts.json` is a conservative starter set (death/birth/recovery/injured/record + plurals, month names, before/after) that deliberately excludes the §29 category words first/crisis/milestone to avoid road-name collisions; it is a data placeholder (GR#15, disclosure-marked) pending Aaron's balance pass, like `salience.json`.
- **ASM-270 (confirm-and-close).** LLM fact-lock = exact match on names/numbers/dates (loosest defensible default).
- **ASM-271 (confirm-and-close).** News archive retains full history, no pruning (v1).
- **Assumption logged — ASM-1209 (CC, signature simplification).** Bulletin/AnnualReview/Epilogue no longer return an error: after SEC-110 persists the name at ingest, generation reads stored names and cannot fail, so the always-nil error returns and the now-unused `correlationID` params were removed.
- **Assumption logged — ASM-1421 (CC, data-location deviation).** The fact-word list lives at `internal/engine/news/news-facts.json` (embedded via `go:embed`) rather than the brief's literal `data/news-facts.json` path.
- **Assumption logged — ASM-1425 (CC, fail-closed guard).** FactLock fails closed — it rejects every rewrite when the embedded fact-word list cannot be loaded or validated, so a broken facts resource can never silently pass generated prose.

- **ASM-1211 (FEAT-084 CC fold).** SEC-113 kept engine.news hand-rolled copy guard (self atomic.Pointer + checkNotCopied, mirroring engine.attract/engine.wellbeing) and extended it to History/Config/Rewriter/Archive/Query (reads return zero value on a copy) rather than migrating to foundation.registry.CopyGuard — migrating would change the code from MET-G2304 to MET-F107, diverge from the two sibling modules, and orphan MET-G2304. CopyGuard migration remains a mechanical option if the lead prefers it.
