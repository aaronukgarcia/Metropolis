# Acceptance criteria — ui.diagrams (MOD-037)

**BOW code:** MOD-037
**Spec refs:** UI-SPEC §2 (`docs/METROPOLIS-MASTER-v2.1.md` line 741: "Block-text diagrams (auto-laid-out): three diagram engines — chain diagrams..., network schematics..., and a text Sankey for the §54 Fiscal Circuit.... These are computed layouts (layered graph drawing, small n), cached until topology changes."); §33/§50 (chain-diagram subject matter — freight/chemical production chains); §54 (the Fiscal Circuit, text-Sankey subject matter); UI-SPEC §4 (dashboards & the drill-through rule — the consumer contract this item must not silently break); `ui.widgets` (MOD-010, the cell-buffer/glyph substrate these engines draw with).
**Date:** 2026-08-11
**Status:** done (Sprint 8)
**Package under test:** `internal/ui/diagrams/` (path from `node claude-bow.js show MOD-037`)
**Standard gates:** see `README.md` — all apply, package for SG-4/SG-7 is `./internal/ui/diagrams/...`.

## User stories

- **US-1.** As **F5 Trade & Logistics** (`FEAT-017`), I need a chain-diagram engine that lays out a production chain as boxes and arrows with live t/day figures on the arrows, so a freight/chemical network reads as a flow diagram instead of a table of numbers (§33/§50).
- **US-2.** As **F2 Finance**'s fiscal-circuit master view (`FEAT-014`), I need a text-Sankey engine that renders the §54 Fiscal Circuit as proportional block-width money bands from sources through the budget to sinks, updating monthly, so the whole economy reads on one screen.
- **US-3.** As **any screen embedding power/water/chemical grids or transit lines**, I need a network-schematic engine (node-and-edge, load-coloured, with a tube-map transit strip variant), so utility/transit topology reads as a real schematic, not a list.
- **US-4.** As **`ui.dash`** (`MOD-038`), I need every rendered diagram element that carries a number (an arrow's t/day figure, a node's load, a Sankey band's amount) to come back from this package tagged with the same-cell source identifier it was computed from, so a diagram embedded in a dashboard tile is drillable like every other tile — this package cannot itself do the drilling (GR#20: the seam to the engine is `int.protocol`, not `ui.diagrams`) but it must not be the place where the source identity is dropped.
- **US-5.** As **any caller re-rendering an unchanged topology**, I need layout computed once and cached until the topology changes, so a 10 Hz UI tick never re-runs a full layered-graph-drawing pass on data that hasn't moved (UI-SPEC §5 performance budget).

## Scope

Three auto-laid-out block-text diagram engines — chain diagrams, network schematics (incl. tube-map transit strips), text Sankey — consuming a caller-supplied topology and drawing onto `ui.widgets`' shared cell-buffer surface. Layered graph drawing for small `n`, cached by topology hash. This package does not fetch its own data from the engine (GR#20 — see AC-1) and does not perform drill navigation itself (that is `ui.dash`'s job) — it is a pure rendering library other UI modules call with data they already hold.

## Acceptance criteria

### Functional

- **AC-1 (GR#20).** This package takes topology as a caller-supplied argument (per code.json's `DiagramAPI` inbound pattern: "topology in, cell-buffer layout out") and makes no call of its own back into `internal/engine` or `internal/protocol` to fetch data. Check: `go list -deps ./internal/ui/diagrams/...` shows no import of `internal/engine/...`, and no import of `internal/protocol` either — this package's only inbound dependency is the topology struct(s) its caller passes in, matching `ui.widgets`' AC-12 purity pattern one layer up.
- **AC-2.** A chain-diagram layout function renders a directed acyclic (or caller-declared-cyclic, rendered with a documented cycle-break rule) production chain as boxes (nodes) and arrows (edges), each arrow annotated with a live figure in its caller-supplied unit (e.g. t/day) — a passing test feeds a known 5-6 node chain (per §33's freight-chain or §50's chemical-network shape) and asserts every edge in the input topology has a corresponding rendered arrow carrying its numeric annotation, and every node has a corresponding rendered box.
- **AC-3.** A network-schematic layout function renders a node-and-edge grid (power/water/chemical) with edge colour driven by a caller-supplied load fraction (0-1), and a distinct tube-map-strip mode for transit lines (stations as stops along a schematic line, not geographically true to the map) — a passing test asserts (a) edge colour/style varies correctly across a range of load-fraction inputs (e.g. 0.1 vs 0.9 produce visibly distinct styles, matching `ui.widgets`' AC-5 independent-heatmap-layer pattern), and (b) the tube-map mode renders stops in line order along a single strip, not at their raw map coordinates.
- **AC-4.** A text-Sankey layout function renders proportional block-width money bands from a caller-supplied set of (source, amount) → (sink, amount) flows (the §54 Fiscal Circuit shape), where each band's width is proportional to its amount relative to the total flow through that stage — a passing test feeds a known flow set (e.g. three sources of unequal size feeding one budget node feeding four sinks of unequal size) and asserts rendered band widths are proportional to input amounts within a documented rounding tolerance (character-cell width is discrete; the tolerance is against a per-cell integer rounding of a continuous ratio, not a wall-clock or fuzzy match).
- **AC-5 (US-4 — the drill-through carry).** Every rendered element that carries a caller-supplied numeric or identity value (an arrow's live figure, a network node/edge, a Sankey band) is returned alongside a hit-test map from cell-buffer region → the same source identifier the caller's topology entry carried in (the caller's own node/edge/flow ID, passed through unchanged — this package does not invent, resolve, or drop it). Check: `go doc ./internal/ui/diagrams` shows a layout function returning both a cell-buffer region and a `map[Rect]SourceID` (or equivalent structural pairing, e.g. each rendered element type carrying its own `SourceID` field) — not just glyphs; a passing test asserts, for a topology where every edge/node/flow has a distinct caller-supplied ID, that the returned hit-test data has one entry per rendered element and every ID round-trips unchanged (the ID that goes in for edge `E7` is the ID attached to `E7`'s rendered arrow, not `E7`'s node, not a renumbered index). **This is the check that rejects a lazy-but-plausible implementation**: a diagram engine that renders correctly-proportioned, correctly-annotated boxes/arrows/bands but returns only a cell buffer (no per-element source mapping) passes AC-2/AC-3/AC-4 and fails AC-5 — and it is AC-5 that `ui.dash` depends on to keep the drill-through rule from breaking the moment a number is inside a diagram instead of a plain tile.
- **AC-6.** Layout is cached, keyed on a hash of the input topology, and only recomputed when that hash changes — a passing test calls a layout function twice with an identical topology and asserts the second call is served from cache (e.g. via an injected call counter on the underlying layout algorithm, asserting it ran once) versus a third call with one changed edge weight, asserting recomputation occurs. **Addendum (dev-team-process.md v1.14, 2026-08-21 — declared gap, not a silent one):** this check proves caching within one `*Engine` held across the two calls the test itself makes; it cannot see, and does not cover, whether a caller **keeps** that `*Engine` across real frames or discards and reconstructs it every render. An `Engine`'s lifetime past construction is entirely its caller's responsibility — this package has no way to reach out and enforce reuse (GR#20: no back-call into anything that could observe or influence the caller). A caller that calls `NewEngine()` fresh every tick will never observe AC-6's cache regardless of how correctly this package implements it, and AC-6 deliberately does not, and cannot, catch that. The owner-side check for "is the cache actually reached" belongs on the caller's own acceptance file (see `ui.screen.finance.md`'s Escalations section).

### Error handling

- **AC-7.** A degenerate topology (zero nodes, a node with no edges, a Sankey flow set that doesn't balance source-total to sink-total) does not panic — it renders a documented empty/partial state (zero nodes: an empty cell-buffer region with no error; a node with no edges: the node box renders alone with no dangling arrow stub). Where the input is malformed rather than merely empty (e.g. an edge referencing a node ID not present in the node set), the layout function returns a registry-sourced error (new `MET-U`-range code) naming the missing node ID, rather than silently dropping the dangling edge or panicking on the missing lookup. Check: a passing test exercises the zero-node case (asserts empty output, no error) and the dangling-edge-reference case (asserts the returned error's registry code is set and names the missing node ID, and that no partial/corrupted layout is returned alongside it).

### Determinism & safety

- **AC-8 (GR#21).** Layout is a pure function of its input topology — the same topology (including tie-breaking within the layered-graph-drawing algorithm, e.g. equal-weight nodes at the same rank) produces byte-identical cell-buffer output and identical hit-test mapping across repeated calls, including across process restarts (no map-iteration-order-dependent placement). Check: `grep -rn "for .* := range" internal/ui/diagrams/*.go` — any range over a `map` feeding node/edge placement order is sorted before use (`grep -n "sort\." internal/ui/diagrams/*.go` corroborates); a passing determinism test runs the same topology through layout N times and asserts identical output, including with an intentionally map-iteration-order-sensitive input (e.g. topology built by inserting into a Go map before being passed in) to catch a hidden `range`-over-map leak in the caller-facing boundary itself.
- **AC-9.** `grep -rn "time.Now" internal/ui/diagrams/*.go` (excluding `_test.go`) returns no matches — layout is topology-driven only, never wall-clock-driven (the 300ms threshold-pulse primitive, if applied to a diagram element, is `ui.widgets`' shared mechanism driven by the caller's tick, not sampled here — matching `ui.widgets`' AC-12 pattern).
- **AC-10.** `go test ./internal/ui/diagrams/... -race -count=1` passes with no data race — the topology-hash cache (AC-6) must be safe if two callers on different goroutines request layout for the same or different topologies concurrently (e.g. F2's fiscal circuit and F5's chain diagram rendering on overlapping UI ticks). A passing test drives the cache from multiple goroutines (`grep -n "go func()" internal/ui/diagrams/*_test.go` finds one).

### Documentation

- **AC-11.** The package doc states module key `ui.diagrams`, cites UI-SPEC §2 and the §33/§50/§54 subject-matter sections, and documents the caller contract from AC-1 and AC-5 explicitly: this package receives topology, never fetches it, and always returns per-element source identifiers alongside layout, because a future caller reusing this package's constructor without wiring AC-5's hit-test map through is exactly how a diagram-embedded number would quietly become a drill-through dead end.

## Out of scope

- Fetching topology from the engine or `int.protocol` — that is the calling screen/dashboard's job (`FEAT-014`, `FEAT-017`, and future consumers); this item only lays out and renders what it is given, and returns source identifiers for what it renders.
- Performing the actual drill navigation (subscribing to a new view, switching screens/panes on `Enter`) when a diagram element is selected — that is `ui.dash`'s (`MOD-038`) drill-through machinery, consuming this package's AC-5 hit-test output.
- The Fiscal Circuit's own data model (which flows exist, their amounts) — §54/`engine.finance` concern; this item only renders a (source, amount) → (sink, amount) shape it is handed.
- Diagram interactivity beyond exposing a hit-test map (pan/zoom within a diagram, collapsing sub-chains) — not called for by UI-SPEC §2's description; flag to Bill if a later screen needs it.
