# Acceptance criteria — secret guard's entropy heuristic vs. hyphenated correlation-ID convention (SEC-021)

**BOW code:** SEC-021 (P3, open)
**Spec refs:** GR#1 (correlation IDs are a project-wide, mandatory convention — every error and every command carries one); the finding's own linkage to SEC-015 (same failure mode: "a guard that cries wolf on ordinary code degrades into a rubber stamp").
**Date:** 2026-08-10
**Status:** active
**Package under test:** `claude-secret-guard.js`.
**Standard gates:** no existing automated harness named in the finding — Tester baseline is the scripted checks in AC-1/AC-2/AC-4 plus whatever test file the guard already has (`grep -rln "secret-guard" *_test.js` if one exists; if not, this item's own AC-4 requires one to be created).

## Acceptance criteria

### Functional

- **AC-1 (the actual fix — distinguish shape, not widen the allowlist).** The high-entropy detector gains a way to distinguish a credential-shaped string from a lowercase-hyphenated word sequence, using **one or more** of the three mechanisms the BOW item itself names as acceptable: a Shannon-entropy floor tuned against real secret shapes, a dictionary-word-ratio test (a string composed mostly of real English words split on hyphens reads as descriptive, not secret), or a mixed-character-class requirement (a real high-entropy secret typically mixes case/digits/symbols; `bogus-injected-phase` is all-lowercase-plus-hyphens). Check: `grep -n "entropy\|dictionary\|charClass" claude-secret-guard.js` shows the chosen mechanism(s) implemented as logic, not as a widened regex pattern or a broadened allowlist (the BOW item explicitly rules both of those out: "do not fix by widening a pattern or by allowlisting a prefix").
- **AC-2 (the three interim entries are removed, not left as debt).** The three exact-literal allowlist entries added as the interim fix (`bogus-injected-phase`, `sec014-original-still-works`, `sec018-original-still-works`) are removed from the allowlist once the heuristic fix lands, and a passing test confirms these exact three literals are now classified as **not** a secret by the improved heuristic **without** being on any allowlist — proving the fix, not the workaround, is what clears them. Check: `grep -n "bogus-injected-phase\|sec014-original-still-works\|sec018-original-still-works" claude-secret-guard.js` finds no matches (i.e. not present anywhere, including in an allowlist array) after the fix.
- **AC-3 (the guard must still catch real secrets — this is the point of the whole exercise).** A passing test feeds at least one representative real-secret-shaped string (e.g. a base64-looking API key, a hex-looking token, a mixed-case+digit+symbol string of typical secret length) through the improved heuristic and asserts it is **still flagged**. Check: `grep -rn "func Test\|it(" claude-secret-guard*.test.js` (or equivalent) finds this positive-control test, and it passes — a fix that reduces false positives by also reducing true-positive sensitivity is not an acceptable outcome and this AC exists specifically to catch that failure mode.

### Error handling

- **AC-4 (Pattern #1 — the false-negative risk is the actual invariant at stake, made checkable).** Because this guard is fail-closed-by-design (SEC-021's sibling note on the "unreachable bypass" being correct-as-designed, not a bug), the real risk this fix must not introduce is a heuristic loose enough that a genuine secret starts reading as "descriptive hyphenated text." AC-1's dictionary-ratio/mixed-class checks are exactly the sort of heuristic that can be widened until it stops working — so this AC requires a **table-driven test with both positive and negative cases side by side** (at minimum: 3 known-descriptive hyphenated identifiers that must pass clean, 3 known-secret-shaped strings that must still flag), run together so a future change to the heuristic cannot silently regress one column while appearing to fix the other. Check: `go test`/`node --test` (whichever the guard's test harness uses) runs this table and all rows pass.

### Documentation

- **AC-5.** `claude-secret-guard.js`'s header comment documents the heuristic's actual distinguishing logic (entropy floor value, or dictionary-ratio threshold, or character-class rule — whichever was chosen) and explicitly states the correlation-ID convention (GR#1) as the motivating false-positive case this logic exists to handle, so a future maintainer tuning the guard understands why "flags every hyphenated lowercase string" is not an acceptable trade-off.

## Out of scope

- SEC-015 itself (a separate, already-`done` finding on the same guard, different specific false positive) — cited here only as the same failure-mode precedent.
- Any change to the guard's fail-closed default or its bypass mechanism — explicitly out of scope per the build log's own note that the "unreachable bypass" investigation was withdrawn as correct-by-design.

## Escalations

- **Likely assumption needed at build time:** the exact numeric entropy floor / dictionary-ratio threshold chosen is a tuning decision no spec dictates — the junior must log an `ASM-` for whichever concrete threshold(s) it picks, citing what test corpus it validated against (this is precisely the kind of "chosen tolerance" v1.7's mandatory spawn block calls out by name).
