# Acceptance criteria — StartSubscriptionPump copy guard (BUG-019)

**BOW code:** BUG-019 (P3, open)
**Spec refs:** the SEC-019/SEC-020 copy-safety chain, of which this is explicitly a narrower sibling (wrong-data, not crash/hang — `e2.subs` is the same pointer as `e.subs`, so `PublishEngineStatus`'s own guard does not fire).
**Date:** 2026-08-10
**Status:** active
**Package under test:** `internal/engine/core/` (`commands.go`, `StartSubscriptionPump`).
**Standard gates:** see `README.md`, package `./internal/engine/core/...`, `-race` required.

## Acceptance criteria

### Functional

- **AC-1 (Pattern #1).** `StartSubscriptionPump` gains the same `checkNotCopied`-style guard already applied to `Engine`'s other `mu`-touching methods (per SEC-016/SEC-018's enumeration of "every other `e.mu.Lock()` call") — check: `grep -n "checkNotCopied" internal/engine/core/commands.go` shows it called at the top of `StartSubscriptionPump`, before the goroutine reading `e.deltaSignal` is started.
- **AC-2 (the specific failure mode named in the finding — verified, not just guarded).** A passing test constructs an `Engine`, takes a copy `e2`, calls `e2.StartSubscriptionPump(ctx, sink)`, and asserts the call is **rejected** (matching AC-1's guard) rather than starting a goroutine that would publish `EngineStatusView`s with a zeroed `Clock` — i.e. the test proves the *specific* wrong-data outcome the finding describes is prevented, not only that some generic guard exists. Check: `go test ./internal/engine/core/... -run TestBUG019 -race -count=1 -v` passes; the test asserts no delta/status is ever published from the copy's pump attempt (not merely that an error was returned — the finding's own subtlety is that `e2.subs` being the same pointer means a naive guard on `subs` alone would miss this, so the test must confirm nothing was actually published via that shared pointer either).

### Error handling

- **AC-3.** The rejection returns the package's existing `ErrEngineCopied` (`MET-E012`) — the same registry-sourced code every other `checkNotCopied` guard in `internal/engine/core` already returns — not a new/different code and not a bare `fmt.Errorf`, and no `EngineStatusView`/delta is published as a side effect of the rejected call (AC-2 already covers the "nothing published" half; this AC covers the code identity). Check: the `TestBUG019` test from AC-2 additionally asserts `errors.Is(err, &errs.E{Code: ErrEngineCopied})` on the copy's `StartSubscriptionPump` return, not merely `err != nil`.

## Out of scope

- Any change to `subs`'s own `PublishEngineStatus` guard — correctly noted in the finding as not itself defective; this item only adds the missing guard at `StartSubscriptionPump`'s own entry point.

## Escalations

- None — "the fix is the same one-line pattern" per the BOW item's own text; no open design question.
