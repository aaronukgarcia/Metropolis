- **Why:** the package is finished and verified but has zero non-test importers. `compose.Wire` (`internal/engine/compose/compose.go`, `registrationOrder` ~l.531, views `viewRegistrationOrder` ~l.650) never constructs `policies.NewPoliciesAPI(correlationID)`. - **Northstar stage:** Baseline One to dogfood ("you decide, the city responds"). The webconsole TS sim has its OWN 8 boolean policies (`PolicyId` in `webconsole/src/sim/types.ts`), none of which are these; see non-goals and Question Q1.
- **Three facts the developer must not assume away (verified in code, 2026-10-30):**
  1. **Policies needs three siblings that are also unwired.** `PoliciesAPI` takes `SetProjections(*projections.ProjectionsAPI)`, `SetFinance(*finance.FinanceAPI)`, `SetTax(*tax.TaxAPI)` (`policies/api.go` l.184-220). Non-test importers of `engine/tax` and `engine/projections` are only unwired packages (policies, fiscal, capexport, education, fuel). Compose today collects tax directly via `finance.CollectTax(finance.TaxRates{IncomeRate: incomeNITaxRateBp}, ...)` (`compose.go` ~l.2640) with a constant rate. So this increment must also construct `TaxAPI` and `ProjectionsAPI` in simState (finance is already there).
  2. **No wired Go module reads any policy coefficient.** `PoliciesAPI.CombinedEffect(coefficientKey, scope)` (`policies/combine.go`) has no non-policies caller. Coefficient keys in the library: `movement.cycling.share`, `movement.car.share`, `wellbeing.parkAccess`, `wellbeing.composite`, `economy.wage.level`, `housing.affordable`, `tax.businessRates.districtMultiplier`, `worklife.weeklyHours`. The 996/40h toggle (`fortyHourWorkingWeek` -> `worklife.weeklyHours`) has its consumer in MOD-080 (open, `engine/worklife`, unwired), so it CANNOT change behaviour in this increment. Wiring the API without a consumer is exactly the built-but-not-wired defect.
  3. **Existing consumer seams that DO exist in compose:** `attract.SetWellbeingModifiers(getter func() (satisfaction, emigration float64))` (an existing, tested seam, see `attack_mod034_apply_round_test.go`), the wages posting path in the finance hook (wages posted through finance, `compose.go` ~l.2505-2640), and the `chrome.topbar` / `f2.finance` views.
- **The lever chosen for the behavioural AC (needs Aaron confirmation, Q2):** primary = `nationalMinimumWage` (`economy.wage.level` +0.05) consumed by the finance hook's wage posting, observable as a changed wages line in the one-money ledger; secondary = `parkAccessProgramme` (`wellbeing.parkAccess`) feeding the satisfaction getter attract already consumes. The 996/40h lever is deferred (MOD-080).

## 2. Acceptance criteria

Surface key: **Cmd** = a new protocol command Kind reaching `compose.handleGameplay` (pattern: `KindSetFunding`: `internal/protocol/commands.go` payload + `commandRegistry`, `core/commands.go`, `stub/engine.go`, `compose.go` ~l.4141). **View** = a new protocol view registered in `viewRegistrationOrder` (fast-follow entry `f8.districts` is the design's named slot for districts; policies list/preview can ride a new `f7.policies` or the same view, dev proposes, lead decides). **Ledger** = `FinanceAPI.Lines`/`LinesByCategory`, visible through `f2.finance`.

- **AC-1 (reachability).** Given a composition from `compose.Wire` with default Deps, when the registered view list and command registry are read, then a policies view name is in `RegisteredViewNames()` and a policies enact command Kind is in the protocol `commandRegistry`, and a Subscribe to that view returns the 9-entry library with name, scope, cost and mechanism. *Mutation:* delete the `viewRegistrationOrder` row or the `handleGameplay` case; the subscribe/enact tests must fail.
- **AC-2 (enact over the wire debits the one money).** Given a fresh composition with treasury funds, when an Enact command for `nationalMinimumWage` (citywide) is submitted through the protocol seam (not by calling `PoliciesAPI` directly), then the command result is Accepted, `finance.LinesByCategory` shows the enactment cost (`cost.enactmentMicroPounds` 4,000,000-class per `data/policies.json`) as a double-entry treasury debit, `TotalMoneyInCirculation` is unchanged by the transfer, and the people/money conservation check (`invariant`) passes the same tick. *Mutation:* make `postOpex` a no-op; the ledger-line assertion fails.
- **AC-3 (recurring enforcement cost).** Given the policy from AC-2 is active, when 3 monthly ticks run, then the `opexMonthlyMicroPounds` line posts once per month (3 lines, not 0, not 1, not 4). *Mutation:* skip `AdvanceMonth`/`postMonthlyOpexLocked` from the new hook; zero lines.
- **AC-4 (the lever changes behaviour).** Given two compositions built from the SAME seed and identical command history except that A enacts `nationalMinimumWage` and B does not, when both run the same 6 monthly ticks, then the wages-category ledger total (household wage inflow, read from `LinesByCategory(wages)` or the `f2.finance` view) differs in the direction of `economy.wage.level +0.05` (A greater than B; a directional test, no absolute number; Aaron owns tuning). *Mutation:* make the wage consumer ignore `CombinedEffect` (or return a constant 0); A equals B and the test fails. This AC is what separates "wired" from "tests green".
- **AC-5 (repeal reverts).** Given AC-4's composition A, when the enactment is repealed via a Repeal command and 3 more months run, then the wage delta vs B returns to zero for the new months and the repeal appears in the view. *Mutation:* leave the coefficient in `CombinedEffect` after repeal.
- **AC-6 (secondary lever, wellbeing to migration).** Given `parkAccessProgramme` enacted in a district, when the satisfaction getter attract consumes is read, then it reflects `wellbeing.parkAccess` through `CombinedEffect` (higher than baseline, directional), and with it repealed it returns to baseline. If the dev cannot land this without changing attract semantics, descope to a documented non-goal with Aaron's say-so, never silently. *Mutation:* hard-wire the getter to the old constant.
- **AC-7 (preview before enact, drift is raised).** Given a policy preview request over the protocol seam, then it returns the projections-backed series tagged Computed/Extrapolated per the package contract, and after enactment plus the data-declared checkpoint cadence a forced divergence raises a queryable PreviewDrift event in the view. *Mutation:* feed the checkpoint the stored preview as "actual"; no drift event raised.
- **AC-8 (conflict warning surfaces).** Given `lowEmissionZone` active, when `congestionCharge` is enacted, then the conflict warning is in the view. *Mutation:* empty `conflictsWith` in the data fixture used by the test.
- **AC-9 (determinism and save).** Given a composition with an active enactment, when saved and loaded (`save_wire.go` participant) and `StateDigest()` is compared, then digests match at the load point; and two same-seed runs produce byte-identical digests. Policies state (enactments, districts, drift events) must be in a registered save participant, not just in memory. *Mutation:* omit the participant; loaded digest differs.
- **AC-10 (invalid input fails closed with registry codes).** Given an Enact for an unknown policy id, an over-length id, or a district-scoped policy with no district, then the command result is a refusal with a registry-sourced error code (add via `tools/plan/add-error.js`), state unchanged, no ledger line. *Mutation:* accept unknown id.
