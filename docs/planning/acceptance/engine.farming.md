## User stories

- **US-1.** As a farm cell, I need a soil-quality value and a regional Biodiversity Index (0-100) driven by habitat share, intensity, chemical load, watercourse quality, and connectivity, so land-use choice has a real, multi-factor ecological consequence, not a single dial.
- **US-2.** As the player choosing crop/livestock and regime (conventional vs organic), I need conventional to trade yield for BDI/aquifer/pollinator damage and organic to trade yield for a price premium, BDI gain, and a real 24-month certification lag, so the choice is a genuine trade-off with a time cost, not a toggle.
- **US-3.** As `engine.season` (already built, registered outbound edge), I need `engine.farming` to consume `SeasonAPI`'s `HarvestCalendar` live rather than duplicate a second harvest-timing curve, per GR#3/GR#15 — the same discipline `engine.wellbeing` and `engine.build` are held to for their own `SeasonAPI` consumption.
- **US-4.** As the pollinator-yield feedback loop, I need fruit/veg/rapeseed yield to multiply by a pollinator index derived from BDI, with self-inflicted collapse a real, reachable outcome of sustained conventional intensification — not a floor-clamped number that can never actually go wrong.
- **US-5.** As `engine.refuse` (§25/§31, now a registered consumer — the `engine.refuse`↔`engine.farming` edge landed in c36778b), I need the food-waste→compost→farm-input chain to have a real consumption point on my side, so composting isn't a described-but-inert flavour loop from farming's end either.
- **US-6.** As `engine.tourism`/`engine.attract`/`engine.wellbeing` (three consumers whose edges remain unregistered — BUG-058 is closed, but no `engine.tourism`/`engine.attract`/`engine.wellbeing`→`engine.farming` edge exists in code.json), I need BDI to be a real, queryable output — countryside/BDI feeds the attraction-portfolio score, BDI is a named term in environment→Attractiveness, and BDI is a named term in the mental-health green-quality driver — so those three systems can eventually consume a live BDI value instead of an invented placeholder.
- **US-7.** As the player watching a regional BDI number move, I need it to be able to both fall (intensification, chemical load, habitat loss) and rise (organic conversion, hedgerow restoration, reduced load) over successive periods, at rates the data file controls — a stock that only ever goes one direction, or one that snaps instantly, is not the biodiversity engine §31 describes.

## Scope

Per-farm soil quality; regional BDI as a driver-decomposed, multi-factor overlay (habitat share, intensity, chemical load, watercourse quality, connectivity); crop/livestock catalogue with stocking density; conventional/organic regime mechanics including certification lag; BDI feedback (pollinator multiplier, fishing-stock/water-treatment-cost gating via watercourse quality, drought/pest resilience); consumption of `SeasonAPI`'s harvest calendar; chain outputs to mill/dairy/abattoir/packhouse/winery; food-miles freshness term. Does not include the three downstream BDI consumers' own math (out of scope, they own their formulas); the compost-input consumption is in scope via AC-10, whose `engine.refuse` edge landed in c36778b.

## Acceptance criteria

### Functional — BDI as a driver-decomposed, two-directional stock

- **AC-1 (GR#20; code.json inbound contract).** A `FarmingAPI` exists exposing per-farm soil-quality and regional-BDI queries plus regime-selection/crop-choice commands, matching code.json's documented pattern "regime coefficients from data; BDI a first-class overlay". Check: `go doc ./internal/engine/farming FarmingAPI` shows both a BDI/soil query surface and a regime-command surface; `grep -n "func.*SetRegime\|func.*ChooseCrop" internal/engine/farming/*.go` confirms regime changes are commands, not direct field writes.
- **AC-2 (§31; additive identity — mirrors `engine.wellbeing.md` AC-2/AC-3, `engine.refuse.md` AC-11).** Regional BDI is computed as `Baseline + Σ(factor.Delta)` across the five named factors (habitat share, intensity, chemical load, watercourse quality, connectivity), each independently sourced from its own driving input, not inferred as a remainder. Check: `go doc ./internal/engine/farming` shows an exported BDI-attribution type naming all five factors; a passing test sums the five independently-computed deltas plus baseline and asserts equality with the returned BDI (`grep -rn "func Test.*[Bb]DISum\|func Test.*[Bb]DIDecomposition" internal/engine/farming/*_test.go`). **Lazy implementation this alone does not catch:** a single blended BDI number can be reverse-engineered into five deltas that sum correctly by construction (AC-3 is the check that rules this out).
- **AC-3 (isolation — the check that makes BDI's causality checkable, exact `engine.wellbeing.md` AC-3 pattern).** Perturbing exactly ONE factor's input (e.g. raising farming intensity while holding habitat share, chemical load, watercourse quality, and connectivity fixed) changes ONLY that factor's named `Delta` — every other factor's delta is byte-identical before and after — and BDI's total change equals exactly the perturbed factor's delta change. Check: a passing test perturbs one input at a time and asserts (a) all non-perturbed deltas are unchanged, (b) the perturbed delta moved, (c) the total's change equals it (`grep -rn "func Test.*[Ii]solat" internal/engine/farming/*_test.go`). **What this rejects:** a weighted-blend-then-post-hoc-attribution implementation (compute one BDI number, then split it proportionally across five display labels) passes AC-2's sum identity but fails here — changing one input moves the *total*, and a proportional split redistributes that change across every label, so every "factor" delta moves, not just the perturbed one.
- **AC-4 (§31; two-directional response — the check the brief specifically demands, US-7).** Regional BDI both DECREASES over successive accounting periods under sustained conventional intensification (rising chemical load / falling connectivity) AND INCREASES over successive periods under sustained restoration (organic conversion, hedgerow/margin/agroforestry add-ons), using data-sourced (not hardcoded, GR#15) rates for each direction that need not be equal (see ASM-308). Neither direction is instantaneous — recovery specifically takes multiple accounting periods, not one tick. Check: a passing test runs two synthetic multi-period scenarios from the same starting BDI — one under sustained intensification, one under sustained restoration — and asserts (a) the intensification scenario's BDI strictly decreases period-over-period until a data-defined floor, (b) the restoration scenario's BDI strictly increases period-over-period until a data-defined ceiling, (c) recovery from a fully-degraded BDI to a materially higher value takes more than one accounting period (`grep -rn "func Test.*[Bb]DI.*[Dd]ecline\|func Test.*[Bb]DI.*[Rr]ecover" internal/engine/farming/*_test.go`). **Lazy implementations this rejects, both directions named in the brief:** (i) a monotone-only-down BDI (no restoration path ever raises it, or restoration is modelled as merely "less bad decline") fails the recovery-increases assertion; (ii) an instant-recovery BDI (organic conversion snaps BDI to a high value the same tick a regime command is applied, e.g. reading the regime enum directly into a BDI lookup table with no period-over-period accumulation) fails the multi-period assertion in (c) — both look entirely plausible on a UI readout that only shows "BDI: 42" once, which is exactly why the check must run the scenario across periods rather than reading one snapshot.
- **AC-5 (§31 pollinator feedback and self-inflicted collapse).** A pollinator index derived from BDI multiplies fruit/veg/rapeseed yield, and sustained low-BDI conventional intensification is capable of driving the pollinator index low enough to cause a materially reduced (not floor-clamped-to-a-safe-minimum) yield outcome within a plausible in-game timeframe — "collapse is possible and self-inflicted" per spec, not merely described. Check: `go doc ./internal/engine/farming PollinatorIndex` (or equivalent) exists and documents its BDI dependency; a passing test drives BDI to a data-defined low value over the intensification scenario from AC-4 and asserts the resulting fruit/veg/rapeseed yield multiplier is materially below 1.0 — specifically below a documented "collapse threshold", not asymptotically approaching but never crossing one (`grep -rn "func Test.*[Pp]ollinator.*[Cc]ollapse" internal/engine/farming/*_test.go`).
- **AC-6 (§31 watercourse-quality gating).** Watercourse quality (one of AC-2's five BDI factors, also independently queryable) gates fishing-stock viability and raises water-treatment cost as it degrades — both are documented, monotonic functions of watercourse quality, not free-standing numbers. Check: `go doc ./internal/engine/farming WatercourseQuality` and its two consumers (fishing-stock gate, treatment-cost function) exist; a passing test asserts both move in the documented direction as watercourse quality falls (`grep -rn "func Test.*[Ww]atercourse" internal/engine/farming/*_test.go`).
- **AC-7 (§31 drought/pest resilience).** A high-BDI farm suffers a smaller yield penalty than an equivalent low-BDI farm under an identical drought-or-pest event input, i.e. BDI is a real resilience multiplier on shock magnitude, not a cosmetic correlate. Check: a passing test applies an identical drought/pest shock to two otherwise-identical farms differing only in BDI and asserts the low-BDI farm's yield loss is materially larger (`grep -rn "func Test.*[Rr]esilience\|func Test.*[Dd]rought" internal/engine/farming/*_test.go`).

### Functional — regime, crops, chains

- **AC-8 (§31 regime trade-off, GR#15 no-hardcoded-literal).** Conventional and organic regimes are each a documented, data-sourced (`data/farming.json`) coefficient bundle — conventional: yield multiplier ≥1.30x (per §31's "+30-40%") relative to organic's 1.0x baseline (ASM-312) with a BDI-decline and aquifer-degradation term; organic: a yield multiplier <1.0x with a price-premium term, a BDI-gain term, and a 24-month certification lag (§31's literal figure) before the premium/BDI-gain terms activate. Check: `grep -nE "1\.3|1\.4|24" internal/engine/farming/*.go` (excluding `_test.go`) finds no bare literal matching these figures outside doc-comment prose — the real values load from `data/farming.json`; a passing test asserts a farm switching to organic does not receive the premium/BDI-gain terms until 24 simulated months have elapsed (`grep -rn "func Test.*[Cc]ertification" internal/engine/farming/*_test.go`).
- **AC-9 (§31 harvest calendar — SeasonAPI reuse, GR#3/GR#15, US-3).** Farming's crop-arrival timing is driven by a LIVE call into `engine.season`'s registered `HarvestCalendar` function, not a second, farming-owned harvest-timing curve. Check: `grep -rn "season\.(HarvestCalendar|SeasonAPI)" internal/engine/farming/*.go` (excluding `_test.go`) shows a real call into the `engine.season` package; `grep -rn "func.*[Hh]arvest" internal/engine/farming/*.go` shows no independently-defined per-month harvest weight table — if a local table exists, this AC fails regardless of whether the numbers happen to match `data/seasonal.json`'s, because a duplicated-and-driftable copy is the GR#3 violation the brief specifically warns against, not merely a wrong number. **False-pass risk:** a farming-local curve that happens to numerically match `data/seasonal.json`'s harvest curve at the time of writing would pass any behavioural "harvests lump seasonally" check while still being a second copy that drifts the moment either file is rebalanced independently — the check requires the *call*, not matching output.
- **AC-10 (§25/§31 compost→farm-input chain — RE-ARMED 2026-08-11, BUG-100: the `engine.refuse`↔`engine.farming` edge landed in c36778b, both directions).** The food-waste→compost→farm-input chain's consumption side (a farm-input yield/cost benefit from applying `engine.refuse`'s compost output) is now a legally wirable, real cross-module call — `node -e "const m=require('./code.json').modules.find(x=>x.key==='engine.farming'); process.exit(m.outbound.calls.some(c=>c.key==='engine.refuse')?0:1)"` exits 0, confirming the edge. `FarmingAPI` must expose a named compost-input type/field AND actually call `engine.refuse` to source it — a documented-but-unwired slot is no longer sufficient now the edge exists. Check: `go doc ./internal/engine/farming` shows a named compost-input type/field; `grep -n "refuse\." internal/engine/farming/*.go` (excluding `_test.go`) shows a real call into `engine.refuse`'s compost-output accessor; a passing test raises `engine.refuse`'s compost output (via the real interface or a fake satisfying it) and asserts farming's yield/cost benefit responds (`grep -rn "func Test.*[Cc]ompost" internal/engine/farming/*_test.go`); `internal/engine/farming/doc.go` no longer cites BUG-058 as a live block for AC-10.
- **AC-11 (§31 chains and food-miles).** Farm output routes to the documented downstream chains (milk→dairy plant, livestock→abattoir→meat processing, grain→mill→bakery, fruit→packhouse, grapes→winery) as typed tonnage handoffs (not a single undifferentiated "farm output" number), and a food-miles freshness term rewards local delivery over imported equivalent goods in the satisfaction/pricing calculation. Check: `go doc ./internal/engine/farming` shows at least five named chain-output accessors; a passing test asserts identical fresh-goods volume from a local farm vs. an imported source produces a higher freshness/satisfaction term for the local farm (`grep -rn "func Test.*[Ff]oodMiles\|func Test.*[Ff]reshness" internal/engine/farming/*_test.go`).

### Error handling

- **AC-12 (GR#7).** Selecting a crop/livestock type not valid for the farm's soil/slope/geology (via `engine.world`'s already-registered edge), or applying a regime command to an unowned/non-agricultural-zoned cell, produces a registry-sourced error (new `MET-E`-range code) rather than a silently-accepted no-op state. Check: `grep -n "MET-" internal/engine/farming/*.go` finds a registry code reference; passing test coverage (`grep -rn "func Test.*[Ii]nvalidCrop\|func Test.*[Uu]nzoned" internal/engine/farming/*_test.go`) — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that no regime/crop-selection state was mutated, not merely that a matching-named test function exists.
- **AC-13.** A regime-change command issued mid-certification-lag (e.g. a second organic conversion attempt before the first's 24 months elapse) is rejected with a typed error, never silently restarting or silently ignored. Check: passing test coverage (`grep -rn "func Test.*[Mm]idCert" internal/engine/farming/*_test.go`).

Check: `grep -rn "func Test.*[Dd]etermnis\|func Test.*[Dd]eterminis" internal/engine/farming/*_test.go`.
- **AC-15 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/engine/farming/*.go` (excluding `_test.go`) returns no matches.
- **AC-16.** `go test ./internal/engine/farming/... -race -count=1` passes; `grep -n "go func()" internal/engine/farming/*_test.go` finds at least one concurrency test (concurrent per-region BDI accumulation across shards within a tick).
