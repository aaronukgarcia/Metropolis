# Acceptance criteria — bound int.solver's Request.Payload before it is wire-reachable (BUG-012)

**BOW code:** BUG-012 (P2, open — gated, see Scope)
**Spec refs:** Weakness pattern #4 ("bound anything attacker-influenced that sizes work or memory"); `int.solver.md`'s own AC-2 (`Request` is stateless/backend-agnostic) and the package's `solveEcho` implementation.
**Date:** 2026-08-10
**Status:** active — but see the gating note: this item's own "Definition of done" ties its landing to whichever of `MOD-068`/`MOD-069`/`INT-004` exposes the solver over a network boundary first, **not** to Sprint 1/2 build order. These criteria are written now so they exist before that gate opens, per the BA's job of running ahead of the build.
**Package under test:** `internal/foundation/solver/` (specifically `cpu.go`'s `solveEcho` and wherever `Request` is decoded off a wire in the eventual remote path).
**Standard gates:** see `README.md`, package `./internal/foundation/solver/...`.

## Acceptance criteria

### Functional

- **AC-1 (Pattern #4, in full).**
  - **(a) Privileged position:** `Request.Payload []byte`, once a remote/network path exists, sizes a `make([]byte, len(req.Payload))` allocation directly from wire-supplied, attacker-influenced data — the same class as SEC-009's `Extent.Width/Height`.
  - **(b) Allowed domain, stated positively:** a named constant (e.g. `MaxRequestPayloadBytes`) bounds `len(req.Payload)`; any request whose payload exceeds it is invalid, full stop — not "reasonable," a specific number tied to the largest legitimate payload the deployed problem kinds actually need (Tester/junior derives this from the largest registered `ProblemKind`'s real payload shape, not an arbitrary round number — if no real problem kind exists yet at implementation time, log an `ASM-` stating the chosen figure and why).
  - **(c) Rejected, not repaired:** an over-limit payload is rejected with a registry-sourced error before any allocation proportional to its claimed size occurs — never truncated, never silently accepted at a smaller size.
  - Check: `grep -n "MaxRequestPayloadBytes\|MaxPayload" internal/foundation/solver/*.go` matches a named constant, and a passing test asserts a request built with `len(Payload) > MaxRequestPayloadBytes` is rejected with a distinct registry-sourced error **before** `solveEcho` (or the eventual real backend) allocates a buffer sized from it — verified by asserting the error surfaces without the test needing to actually allocate the oversized buffer itself (i.e. the check happens on `len()`, not after a `make`).
- **AC-2.** The bound is enforced at the same point for every registered `Solver` implementation, not just `CPUBackend` — i.e. in the registry/selection path (`AC-5`-equivalent of `int.solver.md`) before dispatch to any backend, so a future GPU/cloud backend inherits the check for free rather than needing to remember it (Pattern #1: the invariant "no oversized payload reaches a backend" holds through the shared entry point, not by convention at each backend).

### Determinism & safety

- **AC-3 (GR#21).** The bound check itself never depends on wall-clock time or map iteration order — a straightforward `len()` comparison, confirmed by the existing `int.solver.md` AC-14's `time.Now`/`time.Since` scan continuing to pass with this change added.

## Out of scope

- The actual gRPC/cloud wire decoding this bound protects against — that is `MOD-068`/`MOD-069`/`INT-004`'s own scope; this item only needs the bound to exist and be wired into the shared dispatch path **before** or **in the same change** that first exposes `Solve` over a network boundary, per the BOW item's own "Definition of done."

## Escalations

- **Likely assumption needed at build time, flagged now:** the exact numeric value of `MaxRequestPayloadBytes` cannot be derived today because no real (non-`EchoProblem`) `ProblemKind` payload shape exists yet to size it against. Whoever implements this must log an `ASM-` for the chosen figure — I am flagging this in advance so the junior does not skip it, per v1.7's reciprocal-rejection duty (a junior building to a criterion with an unavoidable open constant must log the assumption when it resolves it, not silently pick a number).
