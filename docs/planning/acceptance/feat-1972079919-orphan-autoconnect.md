# FEAT-1972079919: Bi-monthly Orphan Auto-Connect Sweep

**Feature:** Buildings placed with no road to attach stay unattached (FEAT-1972079907 inc1: no relocation). Later a road is made; new placements auto-attach; the earlier orphans stay disconnected (~50 left as manual work). A background catch-up sweep, once every other in-game month, runs the existing `autoConnect` over every unconnected non-exempt building, charging and ledgering each successful connect exactly as a player-laid connector.

**Mkey:** FEAT-1972079919

## Evidence (why this is P1)

Aaron dogfood 2026-08-28 ~22:34. Gap in FEAT-1972079907: `autoConnect` runs ONLY at place-time (`engine.ts` place path). If there is no road to attach to, the building stays placed with "no road access". Later the player lays a road; NEW placements auto-attach, but the earlier buildings stay disconnected. After a burst of unattached buildings the player is stuck doing manual connector work. Northstar waypoint 2 (dogfood). Parent: FEAT-1972079907 (reuse `autoConnect` / `roadConnect.planConnector`; do not reimplement the router).

## Design

- **Cadence:** inside `advance()`, fire when `tick % (2 * TICKS_PER_MONTH) === 0` (today `TICKS_PER_MONTH = 30` → tick 60, 120, …). Not on the intervening monthly boundary (`tick % 30 === 0` but not `% 60`), not every tick, not on `init()`. Sits alongside the existing monthly aggregate (`evaluateRoadMonitors` at `tick % TICKS_PER_MONTH === 0`). Recommended order: after that monthly auto-scale, before `computeRoadConnectivity` / `computeFlows`, so newly laid connectors are in this tick's connectivity graph and the rest of the tick is consistent (same reason auto-scale already runs first).
- **Universe:** every building currently in `s.buildings` whose spec is not in `CONNECT_EXEMPT_KINDS` (`road` / `motorway` / `rail` / `station` / `pylon` — same set `autoConnect` uses, plus the existing `isRoadSpec` guard) and that does not already touch a road under the same test `autoConnect` / `planConnector` use (`plan.connected`). "Needs a road and is currently unconnected." No construction-time exemption (place-time `autoConnect` already runs immediately).
- **Reuse:** the sweep calls the same `autoConnect` (or one extracted shared helper that both the place path and the sweep invoke). Same router (`roadConnect.planConnector`), same `fittingTier`, same upgrade-on-connect, same `placementCost` / `SPECS` prices (GR#15 — no new hardcoded prices, no new balance numbers). Deleting the shared laying body must turn BOTH place-time and sweep tests red.
- **Ledger + charge:** each successful connect books the same labels and amounts a player-place `autoConnect` would: `Connector ${connSpec.name} (N)` and `Upgraded ${n} road tile(s) to ${connSpec.name}`. One building → its own ledger line(s), not one lump. Funds drop by that building's `totalCost` (`tileCost * path.length` + upgrade delta, all from `placementCost`). Because the spend happens inside `advance()`, the tick conservation identity (`conservation.funds-vs-flows`) must still hold — auto-scale precedent: in-tick capital spend participates in `lastFlows` so the identity balances; ledger labels stay the place-time Connector/upgrade strings, not a new "Catch-up Connect" lump.
- **Order:** candidates processed by building `id` ascending (GR#21; no `Date` / `Math.random`). Identical board + funds → identical connectors + ledger + funds.
- **Unaffordable:** if the next building's full connector `totalCost` exceeds remaining funds, STOP the sweep. No partial tiles for that building; do not skip it to connect a cheaper later orphan. Remainder waits for the next bi-monthly pass.
- **Blocked:** `plan.blocked` buildings stay placed. The sweep does not write `roadNotice` (no sticky-notice spam every 60 ticks); the place-time notice is enough. A successful connect may clear the notice.
- **Replay:** no new journal action type. The sweep rides `tick` / `advance()`, so a genesis replay of a journal whose ticks span a sweep boundary is byte-identical.
- **Home:** webconsole-internal (`webconsole/src/sim/engine.ts` + existing `roadConnect.planConnector`). No Go `engine.roads` edge (GR#25).

## Acceptance Criteria

- **AC-1 (cadence).** The orphan sweep runs inside `advance()` iff `tick % (2 * TICKS_PER_MONTH) === 0` (60 given the existing constant). It does not run on tick 30, 90, … (monthly but not bi-monthly), not on every tick, not on `init()`. Check: `it('AC-1 cadence: orphan sweep fires iff tick % 60 === 0')` — place ≥1 unconnected non-exempt building with a reachable road and funds covering the connector; `advance` to tick `TICKS_PER_MONTH` (30) and assert zero new connector tiles / zero Connector ledger lines from the sweep; `advance` to tick `2 * TICKS_PER_MONTH` (60) and assert the sweep did connect. Period in the test is `2 * TICKS_PER_MONTH` (GR#15), not a magic 60 independent of the constant. **False-pass:** advancing 60 ticks from genesis and only asserting the final board — that hides a tick-30 fire. The intervening month must be asserted as a no-op.

- **AC-2 (universe).** Every non-exempt building that does not already touch a road is a candidate. Exempt kinds are exactly `CONNECT_EXEMPT_KINDS`: `road`, `motorway`, `rail`, `station`, `pylon` (tests read that set / the same guard `autoConnect` uses, including `isRoadSpec` — do not restate a second copy). Check: `it('AC-2 universe: every non-exempt unconnected building is a candidate')` — seed several unconnected houses/shops plus one exempt road/rail/station/pylon that does not "touch" a road; on the sweep tick, every non-exempt orphan that is affordable and unblocked is connected; exempt specs have no connector laid from them. Dogfood shape: place N buildings with no road (they stay unattached); lay a road; new place auto-attaches; the N orphans stay disconnected until the next sweep, then all affordable ones connect. **False-pass:** a test that only seeds houses — exempt-kind exclusion is untested.

- **AC-3 (reuse).** The sweep calls the same `autoConnect` (or an extracted shared helper that the place path also calls). Check: `it('AC-3 reuse: sweep shares autoConnect laying')` plus `grep -n "autoConnect" webconsole/src/sim/engine.ts` showing both the place path and the sweep invoke the same identifier (not a second copy of `planConnector` + ledger). A pair of tests (place-time vs sweep) each assert connector tiles were laid for the same (building, board, funds); emptying / no-op'ing the shared laying body turns BOTH red. **False-pass:** a sweep-local reimplementation of `planConnector` + ledger that would stay green if `autoConnect`'s laying body were deleted.

- **AC-4 (ledger).** Each successful connect books the same labels and amounts as a player-place `autoConnect`: `Connector ${connSpec.name} (N)` and, when upgrades happen, `Upgraded ${n} road tile(s) to ${connSpec.name}`. One entry group per building, not one lump for the whole sweep. Amounts derive from `placementCost` / `SPECS` (GR#15). Check: `it('AC-4 ledger: per-building Connector and upgrade lines')` — control: place-time `autoConnect` one building, capture its ledger label(s)+amount(s); treatment: same building left as an orphan and connected by the sweep; assert matching label strings and matching amounts. Two orphans in one sweep → two Connector lines (and upgrade lines per building that upgraded), never a single combined "Catch-up" / "Orphan" line. **False-pass:** asserting only that *some* negative ledger movement occurred on the sweep tick.

- **AC-5 (charge + conservation).** Funds decrease by the same `totalCost` `autoConnect` would charge for each successful building (connector tiles + upgrade delta; values from `placementCost`, never a new literal). The sweep tick's conservation identity holds (`conservation.funds-vs-flows` / `fundsAtTickEnd === fundsAtTickStart + income - expense`). Check: `it('AC-5 charge: funds decrease by autoConnect totalCost and conservation holds')` — compute expected `totalCost` the same way `autoConnect` does (tileCost × path length + upgrade delta from `placementCost`); assert funds delta equals that sum; assert the conservation check passes on the sweep tick. **False-pass:** asserting funds moved without checking the conservation identity (an in-tick deduct that bypasses `lastFlows` would look like a charge and still fail conservation).

- **AC-6 (order + determinism).** Buildings are processed by `id` ascending. Identical board + funds → identical connector tiles (coords + spec), identical ledger lines, identical funds. No `Date` / `Math.random` on the sweep path. Check: `it('AC-6 order: buildings processed by id ascending')` — seed ≥3 orphans whose cheapest-first order ≠ id-ascending order; assert connectors / ledger appear in id order. Second assertion: run the same sweep twice (or clone state) → byte-identical buildings + ledger + funds. `grep` the sweep path in `engine.ts` finds no `Date` / `Math.random`. **False-pass:** a fixture with a single candidate — order is untested.

- **AC-7 (unaffordable STOP).** If the next building's full connector `totalCost` exceeds remaining funds, STOP. No partial tiles for that building; later (higher-id) orphans wait for the next sweep — the sweep does not skip to a cheaper later building. Check: `it('AC-7 unaffordable: stop with no partial tiles')` — two orphans, id order A then B; funds cover A's full `totalCost` (from `placementCost`) but not A's + B's; after the sweep, A is connected, B is unchanged (same footprint, no new tiles adjacent, no ledger line for B), funds dropped by A's cost only. A third fixture: funds = A's `totalCost` − 1 → A unchanged, zero new tiles, zero Connector lines. **False-pass:** skip-A-connect-B when A is unaffordable but B is cheaper — that is not STOP.

- **AC-8 (blocked, no notice spam).** `plan.blocked` buildings stay placed. The sweep does not set `roadNotice` (or any sticky notice) on a blocked (or unaffordable-stop) pass. Check: `it('AC-8 blocked: stay placed, no sticky notice spam')` — isolate a building so `planConnector` returns `blocked`; run two sweep ticks; assert the building is still present at the same (x,y), no new tiles, and `roadNotice` was not written by the sweep (place-time notice, if any, is not re-asserted every 60 ticks). A successful connect on a later sweep may clear the notice. **False-pass:** asserting only that the building was not deleted — notice spam would still pass.

- **AC-9 (replay).** A journal of ticks spanning a sweep, replayed from genesis, is byte-identical (buildings, connector tiles, ledger Connector/upgrade lines, funds). The sweep rides `tick` / `advance()` — no new journal action type. Check: `it('AC-9 replay: genesis replay spanning a sweep is byte-identical')` — place orphans, lay a road, journal enough `tick`s to cross a `2 * TICKS_PER_MONTH` boundary, capture debug/state, hard-reset genesis replay, re-capture; diff the building set + connector ledger lines + funds — empty. **False-pass:** replaying only `place` actions without the spanning ticks — the sweep would never run.

- **AC-10 (already-connected no-op).** Buildings that already touch a road (`plan.connected`) are no-ops: no charge attributable to them, no extra tiles, no extra ledger lines. Check: `it('AC-10 already-connected: no-op, no charge, no extra tiles')` — seed a building that already touches a road plus (optional) one true orphan; on the sweep tick, the already-connected building's footprint and adjacent road tiles are unchanged, funds/ledger movement equals only the orphan's `autoConnect` `totalCost` (or zero if no orphan). **False-pass:** a city of only disconnected buildings — the no-op path is untested.

## Out of scope

- Retrofitting existing breadcrumb / fragmented roads (Aaron ruling on FEAT-1972079910 — the placement model, not the map).
- Go `engine.roads` / any new `code.json` edge (GR#25: this is webconsole-internal).
- Changing place-time `autoConnect` behaviour (inc1: no relocation; blocked/unaffordable still stay placed with a place-time notice). The sweep is catch-up, not a rewrite of place.
- Reimplementing `planConnector`, `fittingTier`, upgrade-on-connect, or a second connector cost table.
- New balance numbers / new prices (GR#15: `SPECS` / `placementCost` only).
- A new journal action type for the sweep (it rides `advance()`).
- Sticky / repeating "no road access" notices on blocked sweep passes (AC-8).
- Skip-to-cheaper when the next id is unaffordable (AC-7 is STOP).

## Escalations

- **Logged assumption (not a Bill block) — in-tick conservation booking.** Place-time `autoConnect` deducts `s.funds` and writes ledger lines between ticks, so it does not need a `lastFlows` outflow. The sweep runs inside `advance()`, where `conservation.funds-vs-flows` is live. Coder books the same `totalCost` so that identity holds (auto-scale precedent: in-tick capital spend participates in `lastFlows`) while AC-4's ledger labels stay the place-time `Connector …` / `Upgraded …` strings. No new price.
- **Logged assumption — order inside `advance()`.** Sweep after monthly auto-scale, before `computeRoadConnectivity` / `computeFlows`, so this tick's gates/flows see the new connectors. Overrule only if the lead wants a one-tick delay.
- **No GR#25 registration.** Do not add a Go `engine.roads` consumer/edge for this item. Parent FEAT-1972079907 remains the `autoConnect` owner; this item only schedules it.
