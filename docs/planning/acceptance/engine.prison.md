# Acceptance criteria — engine.prison (MOD-056)

**BOW code:** MOD-056
**Spec refs:** §43 Prison, Rehabilitation & Re-entry (`docs/METROPOLIS-MASTER-v2.1.md` lines 577-579: "deepening §28's back end"; estate local jail → category prisons (open/standard/high-security — mix must match offender profile; "holding minor offenders in high-sec *raises* their reoffending"); regime budget per prison: education-in-prison, work programmes, addiction treatment; `ReoffendingRate = base(offence, age) − regime effects − re-entry support (probation capacity, ex-offender employment schemes, housing-on-release)`; youth offending a separate, cheaper pipeline where "every point of prevention beats cure" (§28 youth centres feed in); overcrowding (population > capacity, **including §36 sold places**) "degrades every regime effect at once — the export contract that quietly breaks your rehabilitation numbers"; "the long ledger: rehab spend returns over 5-15 years as crime ↓, workforce ↑ — the **F7 projection** makes the case so the player can choose to believe it"); §36 (Catalogue Supplement 2, line 591, "Prison places | £/prisoner-yr | ties §43; ethics-free money until overcrowding bites" — the sold-places export line this module's overcrowding term must count as occupied capacity); code.json `engine.prison` entry (inbound `PrisonAPI`, "cohort tracking on real citizen records; Slow-Fuse projections", consumers: none registered; outbound calls `engine.crime`, `engine.services`).
**Date:** 2026-08-11 (BA-S11a, first pass)
**Status:** draft-ahead — `MOD-042` (engine.crime) is `open` (this BA's own sibling file, also draft-ahead); this item is not in the ready queue until it lands.
**Package under test:** `internal/engine/prison/` (path from `node claude-bow.js show MOD-056`)
**Standard gates:** see `README.md` — all apply, package for SG-4/SG-7 is `./internal/engine/prison/...`.

## User stories

- **US-1.** As `engine.crime` (MOD-042, the module this package consumes via `CrimeAPI`), I need every sentencing event I emit to be independently re-recorded here as a real admission — not merely trusted as a number crime asserts — so `engine.crime.md` AC-12's justice-chain conservation identity has an independent second source to cross-check against, the way a pipeline of identifiable citizens (Option B) demands.
- **US-2.** As a citizen in the justice system, I need my cohort record (category placed, regime received, re-entry support received, eventual reoffend-or-not outcome) to be tracked against my own `CitizensAPI` record, so "the citizen records make this literal and auditable" (the §40-adjacent framing this module's own code.json pattern text — "cohort tracking on real citizen records" — commits to) is genuinely true, not a city-wide statistic with no traceable owner.
- **US-3.** As the player choosing a prison-category mix, I need placing a low-risk offender in high-security to be **measurably worse** for reoffending than placing them correctly — the spec's explicit, counterintuitive claim — so "stricter is always safer" is not accidentally what the build encodes.
- **US-4.** As the regime budget, I need education, work programmes, and addiction treatment to be three independently-funded lines each with their own attributable effect on reoffending, so a rehab-spend debate can be about which line, not a single blended "prison quality" number.
- **US-5.** As overcrowding (including §36 sold places), I need to degrade **every** regime effect in the same tick when triggered, so "the export contract that quietly breaks your rehabilitation numbers" is a real, all-at-once mechanical consequence, not a story about one line degrading while the others coast.
- **US-6.** As the module's own code.json inbound pattern text states verbatim — "Slow-Fuse projections" — I need rehab-spend funding decisions to submit through `engine.projections`' Slow-Fuse gate with a real projected-consequence payload, exactly as §43's explicit "the F7 projection makes the case" names, and exactly as this module's own registry entry already promises.

## Scope

The prison estate (local jail → category prisons) and category-mismatch penalty; the regime budget's three programmes and their independent reoffending-rate contributions; the reoffending formula (`base − regime − re-entry`) with three independently-sourced terms; the youth-offending pipeline; overcrowding (including §36 sold places) degrading all regime effects simultaneously; the intake ledger that cross-checks `engine.crime.md` AC-12's justice-chain identity; submission of rehab-spend funding decisions to `engine.projections`' Slow-Fuse gate.

## Acceptance criteria

### Functional — intake, cohort tracking, category mix

- **AC-1 (GR#20; code.json inbound contract).** A `PrisonAPI` exists matching code.json's registered pattern "cohort tracking on real citizen records; Slow-Fuse projections": per-prisoner cohort records keyed to `CitizensAPI` IDs are queryable individually, not only as aggregate headcounts, and a Slow-Fuse submission surface exists for funding-cut/rehab-spend decisions. Check: `go doc ./internal/engine/prison PrisonAPI` shows a per-prisoner cohort accessor taking a citizen ID, distinct from any aggregate/summary accessor; a passing test constructs two prisoners and asserts each is independently queryable by ID with independent category/regime/outcome fields (`grep -rn "func Test.*[Cc]ohortRecord\|func Test.*[Pp]erPrisoner" internal/engine/prison/*_test.go`). A lazy-but-plausible violation: an aggregate-only headcount-by-category model with no per-citizen record — this check rejects it by requiring an ID-keyed query.
- **AC-2 (§43/§28 intake ledger — the cross-check `engine.crime.md` AC-12 depends on, and this file's independently-sourced term for the justice-chain identity).** Prison's intake accessor independently records each admission (citizen ID, sentence length, category assigned, sentencing-event reference) as its own ledger entry the moment `engine.crime` sentences an offender — this module does not simply trust a number `engine.crime` reports; it builds its own admission record from the `CrimeAPI` sentencing call it receives. Check: `go doc ./internal/engine/prison` shows an `IntakeLedger`/`Admit` accessor keyed by citizen ID with its own timestamp/source fields; a passing test asserts the **count of independently-recorded admissions** in a synthetic month equals `engine.crime`'s independently-tracked `OffendersSentencedToPrison` figure for the same month — the cross-check `engine.crime.md` AC-12 requires — not merely that `engine.prison` increments a shared counter whenever `engine.crime` calls it (`grep -rn "func Test.*[Ii]ntakeLedger\|func Test.*[Cc]rossCheckAdmission" internal/engine/prison/*_test.go`). **Lazy implementation this rejects:** a `Prison.RecordAdmission(n int)` that just adds `n` to a total, called once by crime with whatever figure crime computed, would make the "cross-check" tautological — the check requires prison to build its ledger entry-by-entry from the sentencing call, so a discrepancy between the two modules' own counts is actually detectable.
- **AC-3 (§43 category-mix mismatch RAISES reoffending — the counterintuitive direction, easy to get backwards).** Placing a minor/low-risk offender in a high-security category produces a **strictly higher** reoffending-rate contribution than placing the identical offender in a category matching their risk profile, all other regime/re-entry conditions held equal. Check: a passing test constructs two identical low-risk offenders, places one in a matched category and one in high-security, runs both through identical regime/re-entry conditions, and asserts the high-security-placed offender's reoffending output is strictly greater (`grep -rn "func Test.*[Cc]ategoryMismatch\|func Test.*[Mm]iscategor" internal/engine/prison/*_test.go`). **Lazy implementation this rejects:** a build that treats high-security as simply "more secure, no behavioural side-effect" (the naive, intuitive-but-wrong assumption — stricter should never be worse) would satisfy "category exists as a field" while silently inverting the spec's explicit causal claim; the check demands the wrong-category case score *worse*, not merely *different*.

### Functional — regime, reoffending formula, youth pipeline

- **AC-4 (§43 three regime programmes, independently isolable — mirrors `engine.social.md` AC-2's decomposition pattern).** Education-in-prison, work programmes, and addiction treatment are three distinct, independently-funded regime lines, each contributing its own subtractive term to the reoffending-rate formula; raising exactly one (holding the other two fixed) measurably lowers reoffending without moving the other two programmes' own attributed contribution. Check: three single-variable tests, one per programme (`grep -rn "func Test.*[Rr]egimeIsolat\|func Test.*[Ee]ducationProgramme\|func Test.*[Ww]orkProgramme\|func Test.*[Aa]ddictionTreatment" internal/engine/prison/*_test.go`). **False-pass risk:** a single blended "regime quality" scalar split three ways for display would pass "three programmes exist" while making them move together on any funding change — the check requires isolating exactly one.
- **AC-5 (§43 reoffending formula, three independently-sourced terms).** `ReoffendingRate = Base(offence, age) − RegimeEffect(AC-4's three programmes) − ReentrySupport(probation capacity + ex-offender employment scheme uptake + housing-on-release status)`, with `Base` sourced from a documented, data-loaded offence/age table (GR#15), `RegimeEffect` sourced from AC-4's accessors, and `ReentrySupport` sourced independently from its three named sub-inputs — no term inferred from an externally observed target rate. Check: six single-variable scenarios (one per named sub-input across the three terms) each asserting `ReoffendingRate` moves in the documented direction while the other two top-level terms stay unchanged (`grep -rn "func Test.*[Rr]eoffendFormula\|func Test.*[Rr]eentrySupport" internal/engine/prison/*_test.go`).
- **AC-6 (§43 youth offending — a distinct, cheaper pipeline).** Youth offenders route through a distinct pipeline/category from adult prison with its own documented, lower capital/opex cost structure and its own prevention-synergy hook consuming `engine.crime`'s registered youth-centre-driven prevention term (not reimplemented here), such that a youth and an adult cohort with identical offence/age-table inputs produce different total system cost. Check: `go doc ./internal/engine/prison` shows a distinct `YouthPipeline` accessor; a passing test asserts the youth-pipeline total cost per offender is lower than the adult-pipeline figure for equivalent offence severity (`grep -rn "func Test.*[Yy]outhPipeline\|func Test.*[Yy]outhCost" internal/engine/prison/*_test.go`).

### Functional — overcrowding and §36 sold places

- **AC-7 (§43/§36 overcrowding degrades ALL regime effects simultaneously — "quietly breaks your rehabilitation numbers").** When population exceeds capacity (including §36 sold places counted as occupied, AC-8), **every** AC-4 regime-effect accessor (education, work, addiction) degrades in the **same tick**, proportionally to overcrowding severity — not one line absorbing the whole penalty while the other two coast. Check: a passing test pushes a prison over capacity (via a sold-places contribution, AC-8) and asserts all three AC-4 accessors measurably decrease in the same tick relative to their at-capacity baseline (`grep -rn "func Test.*[Oo]vercrowdAll" internal/engine/prison/*_test.go`). **Lazy implementation this rejects:** degrading only education (the cheapest to model) while leaving work-programme and addiction-treatment effects untouched would satisfy "overcrowding has a negative effect" while directly contradicting the spec's explicit "degrades every regime effect at once" — the check requires all three to move.
- **AC-8 (§36 sold places counted honestly as occupied capacity).** A sold place (an export-contract capacity commitment to another jurisdiction) is a queryable, distinct commitment from genuine domestic population, but contributes **identically** to AC-7's capacity-denominator calculation as an equivalent increase in domestic population — so the player can see "you sold places and that's why your own regime effects degraded." Check: `go doc ./internal/engine/prison` shows a `SoldPlaces` accessor distinct from `DomesticPopulation`; a passing test asserts increasing sold places at fixed domestic population reduces available regime-effective capacity by the identical amount an equivalent domestic-population increase would (`grep -rn "func Test.*[Ss]oldPlaces" internal/engine/prison/*_test.go`).

### Functional — the long ledger (Slow-Fuse, blocked pending BUG-058)

- **AC-9 (§43 "the F7 projection makes the case" — Slow-Fuse rehab-spend submission, STILL BLOCKED after c36778b; BUG-100 tripwire applied).** Every rehab-spend funding-increase decision is submitted to `engine.projections`' Slow-Fuse gate with a real projected-consequence payload over the spec's documented 5-15-year return window — **blocked pending BUG-058:** code.json still registers no `engine.prison`→`engine.projections` outbound edge (c36778b registered `engine.capexport`↔`engine.prison` and `engine.social`/`engine.education`/`engine.dispatch`→`engine.projections`, but not this pair), despite §43's explicit, named text ("the F7 projection makes the case so the player can choose to believe it") pointing directly at the Slow-Fuse/projections mechanism. Until unblocked, this AC requires a `FuseYears` tag (a value in the documented 5-15 range) attached to any rehab-spend funding-increase command, plus a locally-computed projected-consequence value — mirroring `engine.social.md` AC-10's now-superseded interim pattern for the identical block class; the real cross-module submission is deferred. **Tripwire (mechanical, not a prose label — BUG-100):** `node -e "const m=require('./code.json').modules.find(x=>x.key==='engine.prison'); process.exit(m.outbound.calls.some(c=>c.key==='engine.projections')?1:0)"` must exit **0** (edge still absent). A nonzero exit means the edge has landed and this AC is stale, unarmed prose that MUST be rewritten to a real submission check (mirroring `engine.social.md` AC-10's re-armed form) before the next commit touching `internal/engine/prison/`; Tester/CI treat a nonzero exit here as a hard FAIL, not a silent pass. Until the tripwire fires: Check: `grep -n "FuseYears" internal/engine/prison/*.go` shows the tag on rehab-spend commands with a value in [5,15]; a passing test asserts a rehab-spend increase command without an attached local projection is rejected by prison's own pre-submission check (`grep -rn "func Test.*[Ss]lowFuseRehab\|func Test.*[Ff]useYears" internal/engine/prison/*_test.go`); once unblocked, `grep -n "projections\.(RegisterCurveProvider|Submit)" internal/engine/prison/*.go` shows the real call, and `doc.go` states the block explicitly until then.

### Error handling

- **AC-10 (GR#7).** Admitting a citizen ID not present in `CitizensAPI`, or querying a category that was never registered, returns a registry-sourced error (new `MET-E`-range code) rather than a silently-created placeholder inmate record. Check: `grep -n "MET-" internal/engine/prison/*.go` finds a registry code reference; passing test coverage (`grep -rn "func Test.*[Uu]nknownCitizen\|func Test.*[Uu]nregisteredCategory" internal/engine/prison/*_test.go`) — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that no placeholder inmate record was created, not merely that a matching-named test function exists.
- **AC-11.** A release command for an inmate already released, or a regime-funding command outside its documented valid range, is rejected with a typed error, never silently no-op'd or clamped without the caller knowing. Check: passing test coverage (`grep -rn "func Test.*[Dd]oubleRelease\|func Test.*[Ii]nvalidRegimeFunding" internal/engine/prison/*_test.go`).

### Determinism, safety & scale

- **AC-12 (GR#21).** Category-assignment tie-breaking, regime-allocation ordering under funding shortage, and reoffending-outcome draws use the counter-based hash stream `hash(worldSeed, id, month, purposeTag)` — no shared/global RNG. Check: `grep -n "rand.New\|math/rand\"" internal/engine/prison/*.go` (excluding `_test.go`) finds no shared/global RNG source.
- **AC-13 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/engine/prison/*.go` (excluding `_test.go`) returns no matches.
- **AC-14.** `go test ./internal/engine/prison/... -race -count=1` passes; `grep -n "go func()" internal/engine/prison/*_test.go` finds at least one concurrency test (concurrent admission/release across categories within a tick).
