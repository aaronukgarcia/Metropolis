## User stories

- **US-1.** As the player at M10+, I need to buy or lease a TBM (high capex, distinct from ongoing tunnelling cost) and then tunnel at a per-km rate that genuinely falls as cumulative km increases, so the Boring-Company learning-curve thesis is a real mechanic, not a flavour label on a flat per-km cost.
- **US-2.** As `engine.build` (a registered outbound dependency, MOD-026, per code.json's "tunnel km as BuildAPI orders" pattern), I need tunnel construction to be expressed as ordinary build-queue orders, so tunnelling doesn't reimplement a second construction-scheduling model.
- **US-3.** As `engine.traffic` (a registered outbound dependency), I need a completed road/rail/metro tunnel to be a real routing edge — a crossing that bypasses the escarpment or under-town obstacle without the demolition a surface route would need — so tunnels genuinely change the traffic-assignment graph, not just a cosmetic build entry.
- **US-4.** As `engine.mining` (a registered, correctly-bidirectional outbound dependency), I need tunnel spoil to feed the SAME reclamation-fill mechanic mining's exhausted pits use, quoting the real Samphire Hoe precedent, so reclamation is one shared mechanic (GR#3), not two independent copies that happen to look similar.
- **US-5.** As a player choosing a utility tunnel, I need pipes/cables/chemical lines to be genuinely bundled in one dig (a real cost/schedule saving over separate trenching for each network), so "dig-once bundling" is a checkable capex/time reduction, not prose.
- **US-6.** As a player unlocking Hyperloop at M12 (research-gated), I need the advisor to explicitly frame it as a prestige bet — small passenger volume, monstrous capex, huge attractiveness/reputation gain — distinct in kind from every other transit investment in the game, so a player who builds it understands they bought reputation, not throughput.

## Scope

TBM buy/lease with cumulative-km learning-curve pricing; road/rail/metro/utility tunnel types with dig-once bundling for the utility case; escarpment/under-town crossing without demolition; spoil-to-reclamation-fill output (feeding `engine.mining`'s already-registered reclamation surface); Hyperloop as an M12 research-gated, prestige-framed external link. Does not include `engine.build`'s own queue/materials/lead-time mechanics, `engine.traffic`'s own routing-graph/assignment engine, or `engine.mining`'s own reclamation-site mechanics.

## Acceptance criteria

### Functional — TBM programme and learning curve

- **AC-1 (GR#20; code.json inbound contract).** A `TunnelsAPI` exists exposing TBM-programme state (owned/leased, cumulative km bored) and tunnel-order commands expressed as `BuildAPI` orders, matching code.json's pattern "TBM programme state; tunnel km as BuildAPI orders". Check: `go doc ./internal/engine/tunnels TunnelsAPI` shows a cumulative-km/programme-state query and an order-construction command; `grep -n "build\.(Order|Queue)" internal/engine/tunnels/*.go` confirms tunnel orders are constructed through `engine.build`'s exported order type, not a parallel build-queue.
- **AC-2 (§53 buy/lease, high capex distinct from per-km cost).** Acquiring a TBM (buy or lease, two distinct options with different upfront-vs-ongoing cost profiles) is a one-time or recurring capex event queryable separately from the per-km tunnelling cost that follows, so the two cost components can be independently inspected on F5/F2. Check: `go doc ./internal/engine/tunnels` shows a separate `AcquireTBM` (buy/lease) accessor and a `PerKmCost` accessor; a passing test asserts leasing and buying produce different cost-timing profiles (lease: recurring; buy: one-time capex + lower marginal) (`grep -rn "func Test.*[Aa]cquireTBM\|func Test.*[Ll]ease" internal/engine/tunnels/*_test.go`).
- **AC-3 (§53 per-km learning curve — the check the spec specifically demands).** The per-km tunnelling rate is a monotonically non-increasing function of the SAME TBM's cumulative km bored across ITS OWN programme history (not a flat rate, not a rate that resets per tunnel order), using a data-sourced (ASM-322) decay shape. Check: a passing test bores three sequential tunnel segments with the same TBM and asserts the third segment's effective per-km rate is strictly lower than the first's, with the cumulative-km figure carried forward across the three orders rather than reset (`grep -rn "func Test.*[Ll]earningCurve\|func Test.*[Cc]umulative[Kk]m" internal/engine/tunnels/*_test.go`). **Lazy implementation this rejects:** a flat per-km cost with a one-time "bulk discount" applied only on the FIRST order (front-loaded, not genuinely cumulative) would satisfy "the rate isn't always the same" on a shallow read while failing to reward continued use of the same programme — the check requires the THIRD segment specifically to be cheaper than the first, proving the curve tracks running cumulative km rather than order count or a single threshold.
- **AC-4 (§53 four tunnel types).** Road, rail/metro, and utility tunnels are each a distinct, documented tunnel type; rail/metro tunnels specifically apply a documented cost reduction to the metro system relative to metro built without a pre-existing tunnel ("retro-cheapens §T metro"). Check: `go doc ./internal/engine/tunnels` shows three named tunnel-type accessors; a passing test asserts a metro line routed through an existing rail/metro tunnel costs materially less than the same line built with a fresh surface/tunnel combination (`grep -rn "func Test.*[Mm]etroTunnel.*[Cc]ost" internal/engine/tunnels/*_test.go`).
- **AC-5 (§53 utility tunnel dig-once bundling, US-5).** A utility tunnel bundles pipes/cables/chemical lines in a single dig, producing a documented capex/schedule saving relative to trenching each network separately — a real number, not a narrated convenience. Check: a passing test compares the total capex+schedule cost of routing water/power/chemical-pipeline networks through one bundled utility tunnel vs. three separate surface trenches over the same route, asserting the bundled case is materially cheaper (`grep -rn "func Test.*[Bb]undl" internal/engine/tunnels/*_test.go`). **Lazy implementation this rejects:** a utility tunnel that is mechanically just "a road tunnel with a different label" (same cost function, no actual multi-network routing capability) would satisfy "utility tunnels exist" while providing zero dig-once saving — the check requires a real capex/schedule delta against the unbundled alternative.
- **AC-6 (§53 crossing without demolition).** An escarpment or under-town tunnel crossing does not require demolishing/purchasing the surface structures/land above it (unlike a surface route over the same obstacle, which `engine.build`'s own demolition/purchase cost model would apply), and this exemption is queryable/testable as a real cost-comparison delta, not merely absent from the tunnel's own cost formula by omission. Check: a passing test compares the total land/demolition cost of a tunnel crossing vs. an equivalent surface route across the same built-up escarpment/town-centre corridor, asserting the tunnel route's land/demolition-cost component is zero or near-zero while the surface route's is materially positive (`grep -rn "func Test.*[Nn]oDemolition\|func Test.*[Cc]rossingCost" internal/engine/tunnels/*_test.go`).

### Functional — spoil, reclamation, hyperloop

- **AC-7 (§53/§32 spoil-to-reclamation, GR#3 reuse — the already-registered edge, US-4).** Tunnel spoil tonnage is a real, queryable output that feeds `engine.mining`'s already-registered reclamation-fill mechanic via a LIVE call into `engine.mining`'s package, not a tunnels-local reimplementation of reclamation. Check: `grep -rn "mining\.(Reclaim|SpoilFill)" internal/engine/tunnels/*.go` (excluding `_test.go`) shows a real call into `engine.mining`'s exported reclamation surface; `grep -rn "func.*[Rr]eclaim" internal/engine/tunnels/*.go` shows no independently-defined reclamation-fill mechanic — if a local one exists alongside the call, this AC fails regardless of whether it produces the same numbers, per the same GR#3 standard `engine.farming.md` AC-9 and `engine.refuse.md` AC-4 apply to their own cross-module reuse requirements. Check (test): a passing test asserts tunnel spoil tonnage delivered to a mining reclamation site increases that site's fill level through `engine.mining`'s own accessor (`grep -rn "func Test.*[Ss]poil.*[Rr]eclaim" internal/engine/tunnels/*_test.go`).
- **AC-8 (§53 hyperloop — M12 research-gated, US-6).** Hyperloop is unavailable before an M12 research/unlock gate (documented via `engine.unlocks` or equivalent), carries a passenger-volume cap materially SMALLER than the metro/rail systems it superficially resembles, and its attractiveness/reputation gain per unit capex is materially LARGER than any other transit investment's — the "prestige bet, not a transit backbone" claim expressed as two independently-checkable numeric relationships, not narration. Check: `go doc ./internal/engine/tunnels Hyperloop` (or equivalent) exists; a passing test asserts (a) constructing it before the M12 gate is rejected, (b) its documented passenger-capacity figure is below a documented rail/metro comparator, (c) its attractiveness-gain-per-capex-unit figure exceeds the corresponding figure for at least one other major transit build (`grep -rn "func Test.*[Hh]yperloop" internal/engine/tunnels/*_test.go`). **Lazy implementation this rejects:** a Hyperloop that is "unlocked at M12" in name only, with generic high-capacity/high-cost numbers indistinguishable from a rail upgrade, would satisfy "Hyperloop exists and is gated" while failing the actual prestige-bet claim §53 makes explicit — the check requires the capacity-below/attractiveness-above comparison, not merely the gate.
- **AC-9 (§53 advisor framing).** Attempting to construct Hyperloop surfaces a documented advisor message/flag explicitly naming it a prestige bet (not a throughput solution) before commitment — a real, queryable pre-commitment warning, matching §53's "the advisor says so", not merely a ticker line after the fact. Check: `grep -n "prestige\|advisor" internal/engine/tunnels/*.go` (excluding `_test.go`) finds a pre-construction advisory surface; a passing test asserts the advisory is queryable BEFORE the construction command is issued, not only emitted as a post-hoc event (`grep -rn "func Test.*[Aa]dvisor" internal/engine/tunnels/*_test.go`).

### Error handling

- **AC-10 (GR#7).** Issuing a tunnel order without an owned/leased TBM, routing a tunnel through geology `engine.world`'s prospecting has flagged as unbuildable (if such a flag exists at dispatch time — documented either way), or constructing Hyperloop before the M12 gate, produces a registry-sourced error (new `MET-E`-range code) rather than a silent rejection with no typed cause. Check: `grep -n "MET-" internal/engine/tunnels/*.go` finds a registry code reference; passing test coverage (`grep -rn "func Test.*[Nn]oTBM\|func Test.*[Pp]reGate" internal/engine/tunnels/*_test.go`) — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that the order was rejected with a typed, registry-sourced error rather than a silent no-typed-cause rejection, not merely that a matching-named test function exists.

Check: `grep -rn "func Test.*[Dd]etermnis\|func Test.*[Dd]eterminis" internal/engine/tunnels/*_test.go`.
- **AC-12 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/engine/tunnels/*.go` (excluding `_test.go`) returns no matches.
- **AC-13.** `go test ./internal/engine/tunnels/... -race -count=1` passes; `grep -n "go func()" internal/engine/tunnels/*_test.go` finds at least one concurrency test.

### Documentation
