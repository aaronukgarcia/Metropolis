## Acceptance criteria

### Functional

- **AC-1.** `seal()` gains an atomic-load fast path: an `atomic.Bool` (or equivalent) is checked first; only on the (rare) unsealed→sealed transition does the code take the mutex. Check: `grep -n "atomic\." internal/engine/core/*.go` (excluding `_test.go`) shows the new atomic field, and `go doc` / a source read confirms the mutex `Lock()` is no longer on the common (already-sealed) path.
- **AC-2 (the benchmark is the acceptance test).** A `-benchmem` benchmark on `AdvanceTicks` (the same one Tester-1 used to measure the regression) returns toward the pre-sealing figure (~21-25ns/op territory, not required to hit it exactly, but materially closer to it than the current ~42-56ns) **and** continues to report `0 allocs/op`. Check: `go test ./internal/engine/core/... -bench=. -benchmem -run=^$` output compared before/after by the Tester, both figures recorded in the verdict.

### Determinism & safety

- **AC-3 (Pattern #1 — the fast path must not reopen what seal() exists to prevent).** The exact concurrent-safety invariant `seal()` protects — no `RegisterPhaseHook` succeeds after the engine has begun advancing — must be **unbreakable through the public API** with the new atomic fast path in place, not merely "still passes the old test." Check: `go test ./internal/engine/core/... -run TestSEC003 -race -count=50` passes (repeated count, not a single run, since this exact class of defect is a race that a single run can miss), and the three-way sealer-vs-sealer race test (per the item's own "Definition of done") also passes under `-race -count=1` at minimum, ideally `-count=10`+ if the Tester's time budget allows.
- **AC-4.** No new race is introduced by the atomic/mutex combination itself (a classic bug shape: reading the atomic outside the lock, then acting on stale state inside it) — Tester specifically checks for a TOCTOU window between the atomic check and the mutex-guarded transition, per the Destructive agent's own concurrency mandate, even though this item is dispatched as a bug fix rather than through a fresh Destructive pass.

## Out of scope
