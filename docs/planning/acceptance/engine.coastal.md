## User stories

- **US-1.** As the world simulation, I need small-boat arrival events generated on real shore cells, scaled by era/world-conditions/season and never triggerable by player action, so §30's "never player-triggered" constraint is enforced structurally, not just documented.
- **US-2.** As the reception system, I need arrival events to draw down a finite caseworker-throughput capacity, with a shortfall triggering hotel requisition at real cost plus a satisfaction friction, so "insufficient capacity" has a real, checkable consequence rather than an unlimited queue.
- **US-3.** As a person moving through the status pipeline, I need my case to resolve to either `granted` (becoming a full citizen record via `engine.citizens`, world-profile skill distribution) or `not-granted` (managed departure at cost) after a months-long duration, so the pipeline is a real state machine, not an instantaneous classification.
- **US-4.** As the integration system, I need granted arrivals' integration speed to respond to ESOL/adult-ed provision and job-centre matching — blocked pending BUG-058 finding #5 (no `engine.coastal`→`engine.education` edge).
- **US-5.** As the housing-policy system, I need integration speed and reception approach to respond to a dispersal-vs-concentrated-centres policy setting — blocked pending BUG-058 finding #6 (no `engine.coastal`→`engine.households` edge).
- **US-6.** As the player, I need three real policy sliders (processing funding, housing approach, integration investment) each with a genuine trade-off, no "right answer" — per §30's own framing.
- **US-7.** As the ticker/bulletin (`engine.news`, the registered edge), I need coastal events reported factually, so the game's honesty commitment on this system is structural, not a copy-writing choice.

## Scope

Arrival-event generation on shore cells (frequency scaling, never player-triggered); rescue/coastguard response; reception-and-processing capacity with a caseworker-throughput ceiling and a hotel-requisition overflow path; the granted/not-granted status pipeline and its duration; the three named policy sliders; factual news reporting via the registered edge. No shore-cell geography itself (`engine.world`'s job — see the ASM-207 caveat below), no ESOL/adult-ed mechanics (`engine.education`, pending edge), no housing-policy mechanics (`engine.households`, pending edge), no hotel-building construction (`engine.build`/`engine.tourism`, pending edge).

## Acceptance criteria

### Functional

- **AC-1 (GR#20; code.json inbound contract).** A `CoastalAPI` exists matching code.json's registered pattern "event stream + pipeline stages; policies move throughput coefficients" — an event-stream accessor, a per-case pipeline-stage query, and policy-coefficient setters, all through this interface, never a direct struct reach-in. Check: `go doc ./internal/engine/coastal CoastalAPI` shows all three shapes; `grep -rln "coastal\.\w\+State\.\w\+ = " internal/*/ -r --include=*.go` (excluding `internal/engine/coastal` and `_test.go`) finds no bypassing writes.
- **AC-2 (§30 never-player-triggered arrivals).** Arrival events are generated only by the simulation's own scheduled/seeded process — no exported `CoastalAPI` command exists that lets a caller directly create an arrival event. Check: `go doc ./internal/engine/coastal CoastalAPI` lists no "CreateArrival"/"TriggerArrival"-shaped exported command; a passing test asserts arrival events appear over simulated months from the tick/advance path alone, with no test exercising a direct-creation API because none exists (`grep -rn "func Test.*[Nn]oPlayerTrigger\|func Test.*[Aa]rrivalScheduled" internal/engine/coastal/*_test.go`). A lazy-but-plausible violation: an exported `AddArrivalEvent(n int)` method left "for testing" that a UI command handler could also legally call — this check rejects it by requiring the exported surface itself to lack any direct-creation entry point, not merely that the UI happens not to call one today.
- **AC-3 (§30 era/world/season-scaled frequency).** Arrival-event frequency is a function of at least the world's era/milestone tier and the season (via the registered `engine.coastal` season-linked scaling — see AC-13 for whether this is a live `engine.season` call or pushed data), not a flat per-month constant. Check: a passing test holds era fixed, varies a seasonal input, and asserts the expected arrival-event rate over a fixed number of simulated months differs between two season configurations (`grep -rn "func Test.*[Ss]easonScaledFrequency" internal/engine/coastal/*_test.go`); a second test raises the era/tier input and asserts the rate changes (`grep -rn "func Test.*[Ee]raScaledFrequency" internal/engine/coastal/*_test.go`). A lazy-but-plausible violation: a single `arrivalsPerMonth = 3` constant applied unconditionally — rejected because both tests demand the rate actually respond to a changed input.
- **AC-4 (§30 rescue/coastguard).** Each arrival event triggers a rescue response drawing on coastguard/lifeboat capacity (queryable/consumable via `engine.services`, the registered edge), and a capacity shortfall is distinguishable from a fully-resourced rescue in the event's recorded outcome. Check: `go doc ./internal/engine/coastal` shows a rescue-outcome field on the arrival-event record; a passing test reduces coastguard capacity via `engine.services` (a fake satisfying the interface) below what a batch of simultaneous arrivals needs and asserts at least one event's outcome reflects the shortfall (`grep -rn "func Test.*[Rr]escueCapacity" internal/engine/coastal/*_test.go`).
- **AC-5 (§30 caseworker-throughput ceiling and hotel-requisition overflow — the central defect-catcher).** Reception-and-processing capacity is a finite caseworker-throughput ceiling; when incoming caseload exceeds it, the overflow is routed to a hotel-requisition path carrying a real cost figure and a satisfaction-friction effect, rather than being silently absorbed by an uncapped processing queue. Check: a passing test sets caseworker throughput to a small fixed value, forces caseload above it, and asserts (a) a hotel-requisition cost is recorded and non-zero, and (b) a satisfaction-friction signal is recorded, both only in the overflow case (`grep -rn "func Test.*[Cc]aseworkerOverflow\|func Test.*[Hh]otelRequisition" internal/engine/coastal/*_test.go`). A lazy-but-plausible violation: an unbounded processing queue with no requisition path — this check rejects it by forcing overflow and demanding the cost/friction signals actually appear.
- **AC-6 (§30 granted → citizen record via engine.citizens).** A `granted` case, at the end of its pipeline duration, creates a full citizen record through the registered `engine.coastal`→`engine.citizens` edge, with a skills distribution sourced from a configurable world-profile (not a uniform default), and does not merely flip a status flag inside `engine.coastal`'s own state. Check: `grep -n "engine/citizens" internal/engine/coastal/*.go` (excluding `_test.go`) finds a real import/call; a passing test runs a `granted` case to completion and asserts `engine.citizens`' reported population count (via a fake satisfying the interface) actually increases by one, with the new record's skill field sourced from the configured world-profile rather than a hardcoded default (`grep -rn "func Test.*[Gg]rantedBecomesCitizen\|func Test.*[Ww]orldProfileSkills" internal/engine/coastal/*_test.go`). A lazy-but-plausible violation: a `Status: Granted` field flip with no `CitizensAPI` call — rejected because the check demands the population count actually change through the real interface.
- **AC-7 (§30 not-granted → managed departure at cost).** A `not-granted` case incurs a recorded, non-zero managed-departure cost and does not silently disappear from the pipeline's event history — the ticker's factual-reporting requirement (US-7) needs a real terminal record to report on. - News-bulletin copy/rendering — `engine.news`'s job; this item supplies the factual event record only (AC-12).
- Exact arrival-frequency, caseworker-throughput, hotel-requisition-cost, and pipeline-duration magnitudes — placeholder v1 defaults pending M2 balance pass (ASM-323, ASM-324).

## Escalations

- **BUG-058 findings #5/#6/#7 (block AC-8/AC-9/AC-10).** §30's own prose names ESOL/adult-ed, job-centre matching, dispersal-vs-centres housing policy, and hotel requisition as explicit mechanics, but code.json registers no `engine.coastal`→`engine.education`, `engine.coastal`→`engine.households`, or `engine.coastal`→`engine.tourism`/`engine.build` edge. Filed as a comment on BUG-058, 2026-08-11. All three ACs written blocked-pending-fix; AC-16 is the guard proving the gaps are not silently routed around via unregistered imports. Note `engine.education`'s inbound consumers list is currently empty entirely — this module would be its first registered consumer once the edge lands.
- **Zero registered consumers for `engine.coastal` itself.** Unlike every sibling module in this cluster, code.json shows no module currently consuming `CoastalAPI` — §30 is explicitly "neutral... both sides of the ledger honest" and may genuinely be a leaf system feeding only the ticker (the registered `engine.news` edge) and the citizen population (the registered `engine.citizens` edge) rather than being consumed upstream by anything else. Not treating this as a BUG-058 finding since no spec text names a missing consumer — flagging for Bill in case a UI screen (F-panel) consumer is intended and simply not yet registered.
- **ASM-207 (pre-existing, not newly logged).** `engine.world`'s shore-cell definition is a hand-authored piecewise-linear coastline approximation, not a downloaded Kent coastline dataset. Every arrival-event's shore-cell placement (AC-2/AC-14) inherits this approximation's accuracy limits; this file does not attempt to correct or flag individual cell misclassifications, consistent with `engine.world.md`'s own scope boundary.
- **ASM-323/ASM-324 (logged).** Arrival-frequency scaling, caseworker throughput, hotel-requisition cost multiplier, and pipeline-duration range are placeholder v1 magnitudes — see the assumption records.
