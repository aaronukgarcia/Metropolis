## User stories

- **US-1.** As the player, I need every staffable object (hospital, school, clinic, fire post, …) to demand real operators to RUN it — nurses per hospital, teachers per school — so an under-staffed building runs below capacity, not as an abstract "quality" number with no visible cause.
- **US-2.** As the player, I need every object to also demand repair staff to FIX it, drawn from MOD-072's repair backlog (engineer-days/year scaled by size/class), aggregated city-wide and surfaced to me, so accumulated repair demand is a staffing problem I can see and answer.
- **US-3.** As the labour pool, I need staffing demand to be met by *real citizens with the right skills* — university graduates for nurses/teachers, technical-college trades for repair staff — not a synthetic headcount, so "population + training supply skilled citizens" is the education/employment link actually working.
- **US-4.** As the player, I need a staffing shortfall to be coverable by off-map contractors at a premium cost, so a young city that hasn't yet trained enough of its own nurses/repair staff is not hard-locked — but only expensively and only up to a finite contractor pool.
- **US-5.** As the conservation invariant, I need a citizen to be employed in exactly one role at a time — no citizen simultaneously a nurse and a teacher and a repair worker — so the labour pool cannot be double-counted across demand sources.
- **US-6.** As `engine.finance`, I need staffing costs (local wages AND the off-map contractor premium) to be real budget lines posted through `FinanceAPI`, so staffing is a genuine fiscal pressure, not a narratively-described but financially inert number.

## Scope

Operator demand per staffable object type (nurses/hospital, teachers/school, etc., §54-sourced), repair-staff demand aggregated from MOD-072's MaintenanceView backlog, the labour-pool assignment (real citizens with education-derived skills fill roles via `CitizensAPI`), the off-map contractor fallback at a premium, the one-role-per-citizen conservation rule, and wage/contractor-cost posting through `FinanceAPI`. Directional behaviour only — no staff-per-object ratio or contractor-premium magnitude is invented in this file (see Escalations/ASMs).

## Acceptance criteria

### Functional — operator demand (nurses per hospital, teachers per school)

- **AC-1 (GR#20; code.json inbound contract).** A `StaffingAPI` (or equivalent) exists exposing per-object/per-type staffing queries and command-based assignment, matching the project's contract-first pattern (query surface + command handlers, never a public field setter on another package's state). Check: `go doc ./internal/engine/staffing StaffingAPI` shows query methods (e.g. `OperatorDemandFor`, `RepairDemand`, `FilledStaff`, `Shortfall`) and a command-based mutation path (e.g. `AssignCitizen` / `HireContractor`); `grep -n "func.*Assign\|func.*Hire" internal/engine/staffing/*.go` confirms assignment is a command, not a public field setter.

- **AC-2 (§54 operator demand is per-object-type and data-sourced, not hardcoded — GR#15).** Every staffable object type carries an operator-demand figure (nurses per hospital, teachers per school, etc.) loaded from data (`data.catalogue`'s staffing fields or a dedicated staffing data file), never a hardcoded literal in the staffing package. Check: the demand values on the staffing path are read from the data source (`grep -rn "staffing\|OperatorDemand" internal/engine/staffing/*.go` shows the data-consumption path, and `grep -n "hardcod\|// TODO.*hardcode" internal/engine/staffing/*.go` finds none on the demand path); a passing test changes a fixture object's data-declared staffing figure and asserts the queryable demand changes with it (`grep -rn "func Test.*[Dd]ataSourced\|func Test.*[Oo]peratorDemand" internal/engine/staffing/*_test.go`).

- **AC-3 (§54 directional, not invented ratios).** Demand is directional and class-scaled: a larger/higher-class object demands more operators than a smaller one of the same kind, and distinct kinds demand distinct roles (a hospital demands nurses, a school demands teachers). Check: a passing test asserts `OperatorDemandFor(hospital) > OperatorDemandFor(clinic)` and that a school's demand is teacher-typed, a hospital's nurse-typed — without asserting any absolute per-object number this file does not have (GR#15; the ratios themselves are untuned, see ASM-890).

- **AC-4 (§26/§54 — the engine.services overlap: consume the shared staffing-pool, do not reimplement it — GR#3/#20).** For public-service operator roles (§54's Pie categories: police, teachers, nurses & GPs, firefighters, refuse crews, council officers, social workers, dentists & opticians), demand and staffing are expressed through `engine.services`' registered staffing-pool surface (per `engine.services.md` AC-4/AC-5), so "a nurse shortage is one shortage everywhere" (§26) holds *mechanically* — hospital + elder care + home care draw one pool. Check: `grep -rn "services\.\(StaffingPool\|Staff\)" internal/engine/staffing/*.go` (excluding `_test.go`) shows a live call into `engine.services`' pool surface; `grep -rn "func.*NursePool\|type.*StaffingPool" internal/engine/staffing/*.go` finds **no** locally-authored duplicate pool/ratio table (reject any implementation that re-derives §54's Pie ratios or §26's shared-pool arithmetic inside this package). A passing test asserts reducing one shared pool's available staff degrades the filled-staff query for two distinct service objects drawing it, in the same tick (`grep -rn "func Test.*[Ss]haredPool\|func Test.*[Oo]neShortage" internal/engine/staffing/*_test.go`).

### Functional — repair-staff demand (MOD-072's backlog)

- **AC-5 (MOD-072 demand is consumed, not duplicated — GR#3).** Repair-staff demand is sourced from MOD-072's `MaintenanceView` (engineer-days/year scaled by size/class), aggregated city-wide, not a second repair-demand model in this package. Check: `grep -rn "maintenance\.\(MaintenanceView\|EngineerDays\|RepairDemand\)" internal/engine/staffing/*.go` (excluding `_test.go`) shows a live read of the maintenance surface; a passing test asserts the aggregate repair demand equals the sum of the maintenance module's per-object engineer-day figures, and that a motorway demands more engineer-days than a 50m single road and a hospital more than a wind turbine (MOD-072's own stated class ladder), without this package computing any of those figures itself (`grep -rn "func Test.*[Rr]epairDemand\|func Test.*[Ee]ngineerDays" internal/engine/staffing/*_test.go`).

- **AC-6 (city-wide repair demand surfaced to the player).** The aggregate city-wide repair demand (engineer-days/year) and its shortfall against locally-supplied repair staff are both queryable as distinct values, so the player sees "you need X, you have Y" rather than a hidden backlog. Check: `go doc ./internal/engine/staffing` shows both an aggregate-demand accessor and a shortfall accessor; a passing test drives a city with fewer repair-capable citizens than the aggregate demand and asserts `Shortfall > 0`, then supplies enough citizens and asserts `Shortfall == 0` (`grep -rn "func Test.*[Ss]hortfall\|func Test.*[Aa]ggregate" internal/engine/staffing/*_test.go`).

### Functional — the labour pool (education/employment link)

- **AC-7 (the education/employment link — skills gate assignment).** A citizen can be assigned to a role only if their record carries the matching qualification, sourced through `CitizensAPI`'s education/attainment data: nurse/teacher roles require the graduate-level attainment `engine.education` writes (university stage), repair-staff roles require the trades/technical-college skill pool — an unskilled citizen cannot fill a skilled role. Check: `grep -rn "citizens\.\(Education\|Attainment\|Skill\)" internal/engine/staffing/*.go` (excluding `_test.go`) shows the skill/attainment read routing through `CitizensAPI`; a passing test attempts to assign (a) a citizen with no relevant education and (b) a citizen with the required attainment, and asserts (a) is rejected/leaves the role unfilled while (b) succeeds (`grep -rn "func Test.*[Ss]killGate\|func Test.*[Qq]ualification" internal/engine/staffing/*_test.go`). **False-pass risk:** an implementation that keys assignment on a synthetic "hasJob" flag rather than the education record would satisfy "citizens fill jobs" while severing the education/employment link this feature exists to create — the check requires the qualification to come from the citizen's education/attainment data specifically.

- **AC-8 (the labour pool is real citizens, not a headcount).** The filled-staff figure for any object is exactly the count of real citizen records assigned to that role, queryable down to individual citizens (via `CitizensAPI`'s employment state), so staffing IS the citizen model's `employmentState` + sector, not a parallel synthetic headcount. Check: a passing test assigns N distinct citizens to a hospital's nurse roles and asserts the hospital's filled-staff query returns N and lists those N citizen IDs, and that each assigned citizen's employmentState (read back through `CitizensAPI`) reflects the hospital role (`grep -rn "func Test.*[Rr]ealCitizens\|func Test.*[Hh]eadcount" internal/engine/staffing/*_test.go`).

### Functional — conservation (one citizen, one role)

- **AC-9 (conservation — exactly one role per citizen; the "no double-counting the labour pool" invariant).** A citizen is employed in exactly one role at a time: assigning a citizen to a second role vacates the first (or the assignment is rejected), and the citywide total of filled staffing roles never exceeds the number of employed citizens. Check: a passing test assigns citizen C to role A, then role B, and asserts C no longer appears in A's staff list (one role), and a conservation assertion sums all roles' filled-staff and asserts it never exceeds the distinct-citizen count (`grep -rn "func Test.*[Cc]onservation\|func Test.*[Oo]neRole" internal/engine/staffing/*_test.go`). **This is the check that makes the labour pool real:** a build that lets one citizen satisfy two roles' demand simultaneously would silently inflate staffing coverage — indistinguishable from correct until a later fiscal/coverage number reads a doubly-counted headcount.

### Functional — the off-map fallback (contractors at a premium)

- **AC-10 (off-map contractors at a premium, finite — A6).** A staffing shortfall can be met by off-map contractors, but: (a) the contractor unit cost for a role is strictly greater than the local wage for the equivalent role (the premium), and (b) contractor supply is finite and era-scaled (A6), so the fallback cannot absorb an arbitrarily large shortfall. Check: `go doc ./internal/engine/staffing` exposes contractor cost and a finite contractor-pool capacity; a passing test asserts `ContractorCostPerRole > LocalWagePerRole` for the same role, and that a shortfall exceeding the finite contractor pool leaves a residual unmet shortfall rather than silently absorbing it (`grep -rn "func Test.*[Cc]ontractor\|func Test.*[Pp]remium\|func Test.*[Ff]initePool" internal/engine/staffing/*_test.go`). **The premium magnitude and the finite-pool size are NOT specified anywhere (A6 covers out-commuters, not in-commuting contractors) — this AC checks the directional relationship and the finiteness, never a number (see ASM-891).**

### Functional — wages and fiscal posting

- **AC-11 (wages + premium through FinanceAPI — GR#20; the fiscal pressure is real).** Local staff wages and the off-map contractor premium both post through `engine.finance`'s `FinanceAPI` as real ledger lines, queryable as distinct values (gross wage cost vs. contractor cost), so staffing is a genuine budget drain, not a narratively-described cost. Check: `grep -rn "finance\.\(Post\|Ledger\|Expense\)" internal/engine/staffing/*.go` (excluding `_test.go`) shows the posting call into `FinanceAPI`; a passing test hires one local worker and one contractor and asserts both appear as distinct, nonzero finance entries, and that contractor cost exceeds the local wage line for the same role (`grep -rn "func Test.*[Ww]agePost\|func Test.*[Ff]iscal" internal/engine/staffing/*_test.go`).

### Error handling

- **AC-12 (GR#7).** Assigning a citizen with no valid employment/education state, or assigning against an object with no staffing demand, or hiring from an exhausted contractor pool, returns a registry-sourced error (new `MET-E`-range code) rather than silently creating a zero-value or unaccounted staff record. Check: `grep -n "MET-" internal/engine/staffing/*.go` finds a registry code reference; passing test coverage — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that no staff/assignment record was created as a side effect, not merely that a matching-named test function exists (`grep -rn "func Test.*[Ii]nvalidAssign\|func Test.*[Ee]xhaustedPool" internal/engine/staffing/*_test.go`).

### Determinism & safety

- **AC-13 (GR#21).** Staffing assignment when the labour pool is short of demand is deterministic: allocation order follows a documented priority rule (e.g. sorted by object ID or a data-declared priority weight), never map-iteration order. Check: `grep -n "sort\." internal/engine/staffing/*.go` on any map feeding allocation; a passing determinism test asserts identical assignment across repeated runs and worker counts (`grep -rn "func Test.*[Dd]eterminis" internal/engine/staffing/*_test.go`).

- **AC-14 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/engine/staffing/*.go` (excluding `_test.go`) returns no matches — demand, assignment, and contractor hiring are computed from simulation tick/state, never wall clock.

- **AC-15.** `go test ./internal/engine/staffing/... -race -count=1` passes; `grep -n "go func()" internal/engine/staffing/*_test.go` finds at least one concurrency test (concurrent assignment across objects/roles within a tick).

### Documentation

- **AC-16.** The staffing package's `doc.go` states the module key `engine.staffing`, cites §26, §54, §5.1, §27, and A6, documents the one-role-per-citizen conservation rule (AC-9) in prose, and states explicitly that the per-object operator ratios and the off-map contractor premium are directional/untuned pending balance data (not silent hardcoded numbers). Check: `grep -n "engine.staffing" internal/engine/staffing/doc.go` and `grep -n "§26\|§54" internal/engine/staffing/doc.go` and `grep -n "conservation\|one role" internal/engine/staffing/doc.go` all match.

## Out of scope

- The actual per-object operator ratios (nurses per hospital, teachers per school, §54's other seven Pie categories) and the off-map contractor premium/pool size — untuned balance data, directional only here (see ASM-890/ASM-891).
- MOD-072's maintenance mechanics themselves (aging, efficiency decline, lifetime, multi-fix crew routing) — this feature *reads* its demand (AC-5), it does not build the maintenance system.
- `engine.citizens`' own record storage, education/attainment computation, and mortality/employment-state lifecycle — this feature only reads/assigns through `CitizensAPI` (AC-7/AC-8).
- `engine.services`' own capacity/coverage/funding→quality and §54 Pie arithmetic — this feature consumes the staffing-pool surface (AC-4), it does not reimplement it.
- The UI screen that displays city-wide repair demand and staffing shortfall to the player — this feature exposes the queryable figures (AC-6); the screen is a separate `ui.screen.*` item.
