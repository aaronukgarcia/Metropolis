## What changed since the 2026-08-08 draft

The draft assumed a green field. Sprint 1's close and the first Destructive sweep landed real, binding precedent this item must build to from day one rather than discover later:

- **`engine.core` now seals** after its first `AdvanceTicks` call — `RegisterPhaseHook` on a sealed engine returns `ErrEngineSealed` (`MET-E011`), never a silent accept-but-ignore. Mode-(b) regression replay (AC-3) drives a live engine via `HandleCommand`/`RunCommandLoop`, not `RegisterPhaseHook` directly, so this item does not register hooks itself — but AC-3b below states explicitly that replay must never attempt to register anything against a target engine, precisely because a fixture recorded against a differently-configured engine could otherwise appear to "hang" a Destructive reviewer's attention on the wrong invariant.
- **A closed `Commands()` channel is ambiguous**, per `codePrematureCommandsClose` (`MET-P094`, `internal/engine/stub/engine.go`, BUG-020): a clean shutdown always cancels `ctx` before the transport closes, so observing the channel close while `ctx` is still live means something else closed it from under the intentional sequence. Mode-(b) regression replay drives commands into a live transport exactly the way `StubEngine.Run`/`Engine.RunCommandLoop` do, so it inherits the same ambiguity and must resolve it the same way (AC-3c).
- **`ValidateShardName`'s house model** (`internal/foundation/serialize/savebundle.go`): reject a hostile string outright, state the allowed domain positively ("a single clean path component"), never sanitise. `data.catalogue`'s BA instructions and the wider process now require every BA to apply this model wherever a name-shaped value from untrusted-origin data becomes a path segment — see AC-2b/AC-16 below, which is this item's own instance of Weakness pattern #4.
- **Weakness pattern #1** (an invariant stated in prose is not enforced) applies directly to this item's own AC-1 ("strict arrival order") and AC-7 (`CorrelationID` "preserved verbatim") from the original draft — both were prose claims with no criterion that the public API structurally prevents violating them. AC-1b/AC-7b close that gap.

## User stories

- **US-1.** As the H-REPLAY harness, I need to record every `Command` sent to an engine (stub or real) and every `Event`/`Delta` it emits into a durable fixture file, so that a UI developer can replay stable, reproducible data without a live engine (M0-ENG §2.2).
- **US-2.** As the H-REPLAY harness, I need to replay a recorded command log back into a real engine and compare the resulting state/delta stream against the original recording, so that regressions are caught automatically (M0-ENG §2.2's "regression: replay commands, compare snapshots").
- **US-3.** As `int.serializer`'s only fixture-format consumer named this early, I need to reuse the exact same bundle/shard encoding as saves, so that "the save format IS the fixture format" is literally true rather than a parallel format that drifts (M0-ENG §2.2; `docs/design/save-format.md`).
- **US-4.** As a future Tester/CI job, I need fixtures to be self-describing (protocol version, engine identity, seed) so that a stale or incompatible fixture fails loudly at load time rather than silently replaying garbage (GR#1/#7; `docs/design/protocol.md` §2 envelope rules).
- **US-5 (new).** As the Destructive agent (and any future one), I need every name-shaped value this package reads from a fixture — a fixture's own file name if resolved by caller-supplied string, a recorded `Command`'s payload fields that could themselves be path-shaped — to be treated as hostile input at the point it becomes a filesystem path, exactly as `ValidateShardName` already treats `ShardMeta.Name`, so path traversal cannot re-enter through this package after being closed in `foundation.serialize` (weakness pattern #4).
- **US-6 (new).** As a Tester or a future maintainer reading this package's regression-replay mode, I need a closed `Commands()`/transport channel encountered mid-replay to be distinguishable from an intentional end-of-fixture stop, so a genuinely broken target engine is never misreported as "replay completed successfully" (weakness pattern #1's "an invariant stated in prose is not enforced" — the invariant here being "replay either finishes the fixture or reports why it didn't").

## Scope

Recording engine command/event/delta streams to `fixtures/*.ndjson.gz` via `int.serializer`, and replaying those fixtures into either the UI (static data feed) or an engine (regression comparison).

## Acceptance criteria

### Functional

- **AC-1.** A `Recorder` (or equivalent) exists that, given a `protocol.Transport` (or a tap on one), captures every `Command` sent and every `CommandResult`/`Event`/`Delta` received, in strict arrival order. Check: `go doc ./internal/harness/replay Recorder` shows a type whose methods accept/observe `protocol.Command`, `protocol.Event`, `protocol.Delta`.
- **AC-1b (weakness pattern #1 — invariant enforced, not stated).** "Strict arrival order" is not just documented — verify the API cannot be misused to break it: `Recorder`'s captured-message buffer has no exported mutator other than the tap/observe path itself (no `InsertAt`, no exported slice field, no way for a caller holding a `*Recorder` to reorder or splice already-captured records). Check: `go doc ./internal/harness/replay Recorder` shows no exported field or method capable of reordering captured records after the fact; a passing test feeds messages from two goroutines racing to submit and asserts the resulting fixture's `Record` order is still consistent with *some* valid arrival interleaving (never silently corrupted or duplicated) — `grep -rn "func Test.*[Oo]rder.*[Ee]nforc\|func Test.*[Cc]annotReorder" internal/harness/replay/*_test.go`.
- **AC-2.** Recorded streams are written as fixture bundles under `fixtures/*.ndjson.gz` using `int.serializer`'s `StateSerializer`/`NDJSONSerializer` (not a bespoke encoder) — one `Record` per captured message, `Kind` set to the message's protocol `Kind`/type name. Check: `grep -n "serialize\.\(NDJSONSerializer\|StateSerializer\|WriteShard\)" internal/harness/replay/*.go` matches; `grep -rn "json.Marshal\|json.NewEncoder" internal/harness/replay/record.go` (if any) is limited to constructing `Record.Data`, not a second on-disk format.
- **AC-2b (weakness pattern #4 — named privileged position, positive domain, reject not repair).** Wherever this package resolves a **fixture name** (a caller-supplied string identifying which fixture to record to or play back — e.g. a CLI flag, a test table entry, or a name embedded in an already-loaded fixture that names a *second* fixture) into a filesystem path under `fixtures/`, that name is treated exactly as `ShardMeta.Name` is treated by `serialize.ValidateShardName`: **(a) the privileged position it reaches** is a path segment under `fixtures/` (or a `ShardMeta.Name` handed onward into `int.serializer`'s own `ShardPath`, in which case this package need not re-implement the check — reusing `ValidateShardName` directly is the required and sufficient answer); **(b) the exact allowed domain, stated positively**: a single clean path component — no `/`, no `\`, no `:`, no `..`, not absolute, not volume-relative, no trailing dot or trailing space (identical rule to `ValidateShardName`, reused, not re-derived); **(c) violations are rejected, never sanitised** — a hostile fixture name fails the record/replay call with a registry-sourced error naming the fixture name and the reason, and is never `filepath.Clean`'d, trimmed, or silently substituted with a fallback name. Check: `grep -n "ValidateShardName\|serialize\.ValidateShardName" internal/harness/replay/*.go` shows this package calling the existing function rather than reimplementing path-safety logic; if any fixture-name-shaped value in this package's own surface is validated independently (e.g. a fixture *file* name distinct from a shard name inside one), a passing table-driven test mirrors `savebundle_security_test.go`'s traversal/trailing-dot cases against it (`grep -rn "func Test.*[Ff]ixtureName.*[Tt]raversal\|func Test.*[Rr]ejectHostile" internal/harness/replay/*_test.go`).
- **AC-3.** A `Player` (or equivalent) exists that reads a fixture bundle and replays it either (a) into a UI's `Transport` consumer as a canned `Deltas()`/`Events()` source, or (b) as a `Command` sequence sent to a live engine for regression comparison. Check: `go doc ./internal/harness/replay Player` lists both replay modes (or two distinct exported types, e.g. `UIPlayer`/`EnginePlayer`).
- **AC-3b (new — sealing interaction, mode b only).** `EnginePlayer` (mode b) never calls `RegisterPhaseHook` or any boot-only registration method on the target engine — it drives the target purely through `HandleCommand`/`RunCommandLoop`'s public command surface, the same seam any other client uses post-boot. Check: `grep -n "RegisterPhaseHook" internal/harness/replay/*.go` finds no matches; `doc.go` states explicitly that regression replay assumes the target engine is already fully wired (hooks registered, sealed) before replay starts, and that a fixture recorded against a differently-configured engine is a legitimate mismatch AC-5's diff should surface, not something this package tries to paper over by reconfiguring the target.
- **AC-3c (weakness pattern #1 — premature-close ambiguity, mirroring BUG-020/`codePrematureCommandsClose`).** When `EnginePlayer` (mode b) drives a target engine via a `CommandSource`-shaped transport and that transport's `Commands()`/result channel closes (or a `SendResult`/`SendCommand` call reports failure) before the fixture's command sequence is exhausted, replay reports this as a distinct, named failure (e.g. `ErrReplayTargetClosedEarly`) — never as "replay completed" and never conflated with `context.Canceled` on an intentionally cancelled replay. Check: `go doc ./internal/harness/replay` names this error distinctly from a caller-cancellation error; a passing test drives `EnginePlayer` against a fixture longer than a transport stub that closes mid-sequence and asserts the distinct error, not a false "completed" result (`grep -rn "func Test.*[Pp]rematureClose\|func Test.*[Ee]arlyClose" internal/harness/replay/*_test.go`).
- **AC-4.** Fixture headers carry, at minimum, the protocol version the commands were recorded against (`protocol.ProtocolVersion`), the world seed, and an engine identity/build string, reusing `int.serializer`'s `Header` fields where they already exist (`FormatVersion`, `WorldSeed`, `AppVersion`) rather than inventing parallel fields. Check: `grep -n "WorldSeed\|FormatVersion\|AppVersion" internal/harness/replay/*.go` shows the fixture writer populating these via `serialize.Header`, not local duplicates.
- **AC-5.** Regression replay (mode b of AC-3) compares the live engine's re-emitted `Event`/`Delta` stream (or resulting state snapshot) against the recorded one and reports a pass/fail diff, not just "replayed without crashing". Check: `go doc ./internal/harness/replay CompareResult` (or equivalent) exists, and a passing test asserts a deliberately mismatched fixture produces a non-empty diff (`grep -rn "func Test.*[Mm]ismatch\|func Test.*[Dd]iverge" internal/harness/replay/*_test.go` finds coverage).
- **AC-6.** At least one recorded fixture exists in the repo under `fixtures/` (e.g. a short H-STUB session against "Folkestone-64") usable by `ui.harness` (MOD-014) as its inbound contract. Check: `Get-ChildItem fixtures/*.ndjson.gz` (or `ls fixtures/*.ndjson.gz`) is non-empty, and `go test ./internal/harness/replay/... -race -count=1` includes a test that loads and replays it successfully.
- **AC-7.** `CorrelationID` is preserved verbatim through record and replay for every message that carried one (`docs/design/protocol.md` §2: correlation propagates to every CommandResult/Event/Delta). Check: a passing test asserts a recorded `Command`'s `CorrelationID` matches the replayed copy's (`grep -rn "func Test.*Correlation" internal/harness/replay/*_test.go` finds it).
- **AC-7b (weakness pattern #1 — invariant enforced, not stated).** Verify the API cannot be misused to break AC-7: there is no public constructor or mutator on a `Record`/replayed `Command` that allows a caller to overwrite `CorrelationID` after capture without it being a deliberate, documented fixture-editing operation (if such an operation exists for test-fixture authoring, it is named distinctly, e.g. `Record.WithCorrelationIDForTest`, so a Tester/Destructive reviewer can grep for it and confirm it is never reachable from the normal record/replay path). Check: `grep -n "CorrelationID\s*=" internal/harness/replay/*.go` (excluding `_test.go`) finds no assignment outside the initial capture site.

### Error handling

- **AC-8 (GR#7).** Loading a fixture whose `FormatVersion` major differs from the reader's supported major, or whose recorded `protocol.ProtocolVersion` differs from the running build's, fails loudly with a registry-sourced error (a new code in this package's own claimed `MET-<layer>` sub-range — see AC-8b — added to `data/errors.json` per `errs.New`), never a silent best-effort replay. Check: `grep -n "MET-" internal/harness/replay/*.go` finds at least one registry code reference, and a passing test exercises the version-mismatch path (`grep -rn "func Test.*[Vv]ersion" internal/harness/replay/*_test.go`) — **GR#7 assertion, stated explicitly (BUG-100):** the test asserts the returned error's registry code matches AND that no best-effort replay of the mismatched fixture was performed, not merely that a matching-named test function exists.
- **AC-8b (GR#7; BUG-008's lesson).** Before claiming a new `MET-<layer>NNN` sub-range for this package's own codes (AC-8's version-mismatch code, AC-2b/AC-3c's dedicated codes), the range is checked against **both** `data/errors.json`'s `ranges.reserved` table **and** a live source scan (`grep -rn "MET-[A-Z][0-9]" internal/ cmd/`) — not the table alone, per BUG-008's root cause (a collision that existed only in source comments, undetected because only the table was checked). The chosen range and the check performed are recorded in `doc.go`. Check: `data/errors.json`'s `ranges.reserved` table gains an entry for this package's chosen sub-range in the same commit that first uses a code from it (SG-5 permits this path); `internal/harness/replay/doc.go` states the range and that both checks were performed.
- **AC-9.** A corrupt or truncated fixture (bad gzip stream, hash mismatch via `int.serializer`'s `ValidateBundle`) produces a typed error naming the fixture path and the underlying cause, never a panic. Check: `go test ./internal/harness/replay/... -race -count=1` passes including a corrupt-fixture test (`grep -rn "func Test.*[Cc]orrupt" internal/harness/replay/*_test.go`).
- **AC-10.** Recording continues to a partial, still-loadable fixture if the engine/UI process is interrupted mid-session (no requirement to buffer the whole session in memory before any bytes are durable) — or, if the design instead buffers and flushes atomically at close, that choice is documented and a killed-mid-record scenario is explicitly out of scope (see Escalations). Check: `internal/harness/replay/doc.go` states which of the two behaviours was chosen and why.

### Determinism & safety

- **AC-11 (GR#21).** Replaying the same fixture twice into the same engine build/seed produces byte-identical comparison results (`AC-5`'s diff is empty both times, or if mismatched, identically mismatched). Check: a passing test replays the same fixture twice and asserts identical `CompareResult` output (`grep -rn "func Test.*[Dd]eterminis" internal/harness/replay/*_test.go`).
- **AC-12 (SG-7 scoped; GR#21).** `grep -rn "time.Now\|time.Since" internal/harness/replay/*.go` (excluding `_test.go`) returns no matches, or every match is confined to a clearly-labelled recording-session-wallclock field that is diagnostic-only and never fed into `Command.IssuedAtTick` or any replayed value (per `docs/design/protocol.md` §2: "Never wall clock" for `IssuedAtTick`).
- **AC-13.** `go test ./internal/harness/replay/... -race -count=1` passes with no data race when recording concurrently with normal engine/UI operation (recording must not require pausing either loop). Check: `grep -n "go func()" internal/harness/replay/*_test.go` finds at least one concurrency test.
- **AC-13b (new — copy-safety, following SEC-014/SEC-016/SEC-019's precedent).** If `Recorder`/`Player`/`EnginePlayer` hold a mutex alongside any reference-type field (a map, slice-of-pointers, or channel) — the exact shape `engine.core`'s `Engine` and `internal/protocol`'s `SubscriptionServer`/`InProcTransport` were all found vulnerable in (SEC-014/SEC-016/SEC-019, nine types repo-wide per SEC-020's enumeration) — the same copy-safety guard is applied: an identity check (`self` pointer comparison) before any lock is taken, rejecting a struct-copied receiver with a registry-sourced error rather than risking a permanent silent deadlock or a torn-map crash. Check: if any exported type in this package holds `sync.Mutex`/`sync.RWMutex` plus a reference-type field, `grep -n "self\s" internal/harness/replay/*.go` shows an identity guard following the `Engine.self`/`SubscriptionServer.self` pattern, and a passing test constructs a struct copy and asserts a rejection rather than a hang (`grep -rn "func Test.*[Cc]opy" internal/harness/replay/*_test.go`); if no type in this package combines a mutex with a reference field, `doc.go` states this explicitly so a future Destructive sweep doesn't have to re-derive the answer from scratch.

## Out of scope

- H-STUB itself (`MOD-008`) — this item only records/replays whatever transport it is pointed at; it does not build the stub engine.
- `ui.harness`'s (MOD-014) snapshot-assert machinery and latency-budget CI — that item consumes this one's fixtures but owns its own comparison logic.
- The binary serializer format (`BinarySerializer`, reserved in `int.serializer`, not implemented) — fixtures stay NDJSON+gzip until that lands.
- A resync/replay-request protocol extension to `int.protocol` — v1 has none (`docs/design/protocol.md` §7.2); this item works within the existing envelope.
- Cross-machine fixture portability testing beyond what `int.serializer`'s determinism guarantee already covers.
- Re-implementing `ValidateShardName`'s logic — AC-2b requires reuse, not a parallel implementation; a second implementation of the same rule is itself a Weakness-pattern-#2-shaped risk (duplicated value needing a drift test) this item should simply avoid by calling the original.
