## The August tourism stress scenario, defined precisely (S11 exit-gate clause)

§44's only testable prose is "August is a logistics boss-fight your July projections warn you about" — narrative, not a criterion. This file defines the scenario and its pass/fail condition so the S11 exit gate has teeth (v1.9: every AC's check must be able to fail an implementation that merely runs to completion).

**Scenario shape:** a fixture city runs from July through September (inclusive) at a fixed citizen/visitor-generation configuration, with `engine.season`'s real August multiplier live (summer ×3 per §44, sourced from `data/seasonal.json` via `SeasonAPI` — never a duplicated August constant, GR#3/GR#15). No wall-clock timing is asserted anywhere in this scenario's pass condition.

**FAIL if any of the following hold** (AC-13 implements this as a single scenario-level test with three independently-checkable sub-assertions):

1. **Conservation violation.** Visitor counts (day-trippers + staying visitors), once admitted, are not conserved across the scenario the way citizens are (§5.2's determinism/conservation doctrine, mirrored for visitors) — a visitor silently vanishes or duplicates outside a documented departure event.
2. **Capacity-cap breach.** The realised staying-visitor count exceeds the sum of configured accommodation-stock capacity (hotels + B&Bs + campsite/caravan + holiday lets) at any point in the scenario — a build that lets the attraction-portfolio score scale visitor numbers without checking the accommodation ceiling fails this, even if every other AC's prose is satisfied.
3. **Backlog that never drains.** A capacity-bound queue (attraction-access queue, or the accommodation waitlist) that grows through the August peak has not shrunk to within 10% of its pre-August (July) baseline value by the end of September — a **relative** bound (peak-vs-recovery, matching `harness.synth`'s own `RegressionThreshold`=0.10 pattern), never an absolute count or a wall-clock duration. A build that lets the August backlog become a permanent structural queue (never designed to drain) fails this even though it "ran to completion".

**PASS is not "the scenario completed without a panic."** A scenario that runs to completion while breaching FAIL condition 2 or 3 is exactly the lazy-but-plausible implementation this AC exists to catch — see AC-13.

## User stories

- **US-1.** As `engine.destination` (registered consumer), I need a `TourismAPI` exposing the decomposed portfolio-score draw, so destination's own regional-draw machinery (§48) can reuse tourism's scoring rather than duplicating it (ASM-326).
- **US-2.** As the seaside-curve mechanic, I need the summer ×3 seasonal multiplier sourced live from `engine.season`'s `SeasonAPI` (the registered edge), so August's peak is never a second, drifting copy of the same number `engine.season.md` AC-2/AC-8 already own.
- **US-3.** As the housing market, I need holiday-let conversion to actually remove units from workforce housing stock (§44/§21), so "rents up, workforce housing squeezed" is a real supply-side effect, not flavour text — blocked pending BUG-058 finding #3 (no `engine.tourism`→`engine.households` edge).
- **US-4.** As the fiscal system, I need bed-tax revenue to be queryable by `engine.tax`, so §39's "tourist bed tax (§44)" line item is a real skim, not an unconnected number — blocked pending BUG-058 finding #4 (no `engine.tourism`→`engine.tax` edge).
- **US-5.** As the player reading July's projections, I need August's stress (queues, waste, policing load) to be visible ahead of the month it happens, consistent with the anti-ambush projections contract (§13, `engine.projections.md`), so "your July projections warn you about" (§44) is literal.
- **US-6.** As the reputation system, I need tourism income to degrade after a reputation shock (crime wave, sewage-outfall event) with a lag, so "a strong second income, and a trap as a first one" (§44) is a real asymmetric risk, not a static seasonal number (ASM-319).
- **US-7.** As `engine.cafe`, I need my vitality index to be a real input to tourism's attraction-portfolio score ("café culture §41"), so a strong café strip genuinely feeds tourism draw — blocked pending BUG-058 finding #2 (no `engine.tourism`→`engine.cafe` edge).

## Scope

The parallel visitor population stream (day-trippers, staying visitors); the attraction-portfolio draw formula and its season/reputation/access multipliers; accommodation-stock capacity enforcement; the holiday-let housing-conversion mechanism (pending edge); visitor spend and bed-tax accounting (bed-tax queryability pending edge); the August stress scenario and its pass/fail definition. No accommodation-building construction mechanics (that is `engine.build`), no actual housing-market rent computation (`engine.households`), no news-bulletin rendering of tourism events (`engine.news` itself).
