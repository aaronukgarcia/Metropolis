# Acceptance criteria — claude-plan-guard.js's literal NUL byte (BUG-015)

**BOW code:** BUG-015 (P3, open)
**Spec refs:** GR#1/GR#11 (hook code is high-privilege, least-reviewed — a binary-flagged diff is invisible to pre-commit security review); Weakness pattern #1 applied to review-ability rather than a runtime invariant.
**Date:** 2026-08-10
**Status:** active
**Package under test:** `claude-plan-guard.js` (`hashFiles()`).
**Standard gates:** no automated harness for this file; Tester baseline is the scripted checks in AC-1/AC-2/AC-3.

## Acceptance criteria

### Functional

- **AC-1.** The literal NUL byte inside `hashFiles()`'s intended `h.update(' ')` separator call is replaced with an actual space character. Check: `grep -c $'\x00' claude-plan-guard.js` (or `Select-String -Pattern "`0"` equivalent) reports zero NUL bytes anywhere in the file.
- **AC-2 (review-ability, the actual point of the fix).** `git diff` (or `git show`) on a subsequent one-line change to `claude-plan-guard.js` renders as a normal text diff, not `Binary files a/claude-plan-guard.js and b/claude-plan-guard.js differ`. Check: make a trivial whitespace-only change in a scratch branch/worktree after the fix, run `git diff -- claude-plan-guard.js`, and confirm readable diff output (Tester does this as a live check, not a static read).
- **AC-3.** Any stored/compared hash value that depended on the old NUL-separated hashing scheme is re-baselined, not left to silently mismatch — check `grep -n "hashFiles\|storedHash\|expectedHash" claude-plan-guard.js` for where such a comparison lives, and confirm the Tester re-runs whatever check consumes it (e.g. a plan-integrity check) and gets a clean pass against the **new** hash, not a false failure from comparing new-format hashes against old-format stored ones.

### Error handling

- **AC-4.** `hashFiles()` continues to function identically for its actual purpose (whatever integrity/change-detection role it plays in `claude-plan-guard.js`) after the fix — a passing before/after comparison on the same input file set shows the same *set* of distinguishable hashes (just computed with the corrected separator), not a collapse of previously-distinct entries into collisions.

## Out of scope

- Any broader review of `claude-plan-guard.js` beyond this one function — pre-existing at HEAD per the item's own note, not introduced by any current work, and not this item's job to re-audit wholesale.

## Escalations

- None — mechanical fix, precisely scoped by the BOW item's own "Definition of done."
