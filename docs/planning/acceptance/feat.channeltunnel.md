## User stories

- **US-1.** As the player, I need the Channel Tunnel to be **TBM-driven** — consuming `engine.tunnels`' TBM programme and its cumulative-km learning curve — so the mega-tunnel's per-km cost genuinely falls as the boring machine accumulates kilometres, not a flat cross-water price tag (§53).
- **US-2.** As `engine.tunnels` (MOD-065), I need the cross-water mega-tunnel to be expressed as **ordinary tunnel orders** through the registered TBM/BuildAPI surface, so the Channel Tunnel does not reimplement a second boring-machine or construction-scheduling model (GR#3).
- **US-3.** As `engine.rail` (MOD-060), I need the tunnel's **road/rail/metro/utility bundling** to be the same dig-once saving the tunnels module already owns, so one cross-water bore carries multiple networks at a real capex/schedule discount, not four separate underwater digs.
- **US-4.** As `engine.mining` (MOD-046), I need the tunnel's **spoil to feed the shared reclamation-fill** mechanic (Samphire Hoe), so the spoil is reclamation land, not a waste tally — the same shared mechanic every tunnel already uses (§53/§32).
- **US-5.** As the player, I need the advisor to **frame it as a prestige bet** — not a transit backbone — before commitment, so the monstrous capex buys reputation/connectivity prestige, not throughput, and the player knows which they are buying (§53, "the advisor says so").
- **US-6.** As the player, I need it to be a **long-horizon, multi-year, reserved-slot** build, so it is the future-dev prestige bet the milestone ladder reserves, not an early-game throughput tool.

## Scope

The Channel Tunnel as a specialised cross-water mega-tunnel: TBM-driven tunnelling consuming `engine.tunnels`' learning curve; cross-water tunnel orders expressed through `TunnelsAPI`/`BuildAPI`; road/rail/metro/utility dig-once bundling via the shared bundling mechanic; spoil-to-reclamation-fill via `engine.mining`; the prestige-bet advisor framing (mirroring the Hyperloop framing); the M11 reserved-slot gate and multi-year build horizon. No TBM-programme/learning-curve machinery (`engine.tunnels` — consumed), no tunnel-order/construction machinery (`engine.build`/`engine.tunnels` — consumed), no reclamation-site mechanics (`engine.mining` — fed), no rail/metro interconnection machinery (`engine.rail` — fed), and no final figure magnitudes (Aaron's balance pass).

## Acceptance criteria

### Functional — TBM-driven mega-tunnel (consume, don't reinvent)

- **AC-1 (GR#20; shared-package surface, feature-shape per ASM-688).** A Channel-Tunnel surface exists on the shared `internal/engine/tunnels` package (a specialised mega-tunnel type set, not a fork), distinct from `engine.tunnels.md` AC-1's `TunnelsAPI` TBM-programme surface, and consuming `TunnelsAPI` and `RailAPI` via direct calls rather than reimplementing either. Check: `go doc ./internal/engine/tunnels` shows a Channel-Tunnel accessor distinct from `TunnelsAPI`'s; `internal/engine/tunnels/doc.go` notes the shared-package, no-separate-inbound-contract arrangement (`grep -n "feat.channeltunnel" internal/engine/tunnels/doc.go`), mirroring `feat.megafacilities.md` AC-1's convention.
- **AC-2 (§53 TBM learning curve — the mega-tunnel rides the SAME curve, GR#3 reuse).** The cross-water tunnel's per-km cost is computed by `engine.tunnels`' cumulative-km learning-curve surface (`engine.tunnels.md` AC-3), so the mega-tunnel's per-km rate falls with the TBM's cumulative kilometres across its whole programme history — there is no channeltunnel-local per-km cost formula or a second boring machine. Check: `grep -rn "tunnels\.\|TunnelsAPI" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) shows a real call into `engine.tunnels`' cost surface; `grep -rn "perKm\|[Ll]earningCurve" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) shows no local cost-curve reimplementation. **False-pass risk:** a flat cross-water price tag would pass a "tunnel has a cost" read while §53's learning curve is unmet — the check requires the cost to resolve through `engine.tunnels`' curve (ASM-689).
- **AC-3 (§53 tunnel orders as BuildAPI orders — no second construction model).** The cross-water tunnel is constructed as ordinary tunnel orders through `engine.tunnels`/`engine.build`'s order surface, not a channeltunnel-local construction queue. Check: `grep -rn "build\.\|tunnels\.\(Order\|Queue\)" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) shows the order path routed through the registered surface; no parallel build-queue type is declared in the channeltunnel files.
- **AC-4 (GR#15; capex/length/per-km/bundling-save are data-driven).** The cross-water tunnel's capex, length, per-km base rate, and the road/rail/metro/utility bundling saving are loaded from `data/channeltunnel.json`, never hardcoded Go literals, and the data file defines the cross-water tunnel's figures distinctly so the mega-tunnel is a real scale step, not a renamed road tunnel. Check: a passing test mutates the cross-water tunnel's bundling-save figure in the loaded fixture and asserts the computed bundled cost reflects the change; `grep -nE "[0-9]+" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) finds no bare cost-shaped numeric literals. **Balance-regime note:** magnitudes are placeholders (AC-13); this AC checks *data-driven*, not any magnitude.

### Functional — bundling, spoil, prestige framing

- **AC-5 (§53 dig-once bundling — the SAME mechanic `engine.tunnels` AC-5 owns, GR#3 reuse).** The cross-water tunnel's road/rail/metro/utility bundling produces a documented capex/schedule saving relative to trenching/boring each network separately, computed by the **same** bundling surface `engine.tunnels.md` AC-5 owns — there is no channeltunnel-local bundling cost delta. Check: `grep -rn "tunnels\.\|Bundl" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) shows the bundling saving resolving through `engine.tunnels`' surface, not a local delta; a passing test routes the four networks through one cross-water bore and asserts the bundled total is materially cheaper than four separate bores (`grep -rn "func Test.*[Bb]undl.*[Cc]hannel\|func Test.*[Dd]igOnce" internal/engine/tunnels/*_test.go`). **False-pass risk:** a "utility tunnel with a different label" that reuses the road-tunnel cost function with no multi-network routing would pass a "bundling exists" read while providing zero dig-once saving — the check requires the saving to resolve through the shared mechanic (ASM-690).
- **AC-6 (§53/§32 spoil-to-reclamation — via `engine.mining`'s already-registered edge, GR#3 reuse).** The cross-water tunnel's spoil tonnage feeds `engine.mining`'s reclamation-fill surface via a live call (the Samphire Hoe precedent), the same already-registered `engine.tunnels → engine.mining` edge `engine.tunnels.md` AC-7 uses — not a channeltunnel-local reclamation path. Check: `grep -rn "mining\.\|Reclaim\|SpoilFill" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) shows the call into `engine.mining`; `grep -rn "func.*[Rr]eclaim" internal/engine/tunnels/channeltunnel*.go` shows no independently-defined reclamation mechanic; a passing test asserts spoil delivered to a mining reclamation site increases that site's fill level through `engine.mining`'s own accessor (`grep -rn "func Test.*[Ss]poil.*[Rr]eclaim.*[Cc]hannel" internal/engine/tunnels/*_test.go`). **Dependency note:** the `engine.tunnels → engine.mining` edge is already bidirectionally registered (per `engine.tunnels.md`), so this AC's reuse is a *real* edge, not an assumption (ASM-691).
- **AC-7 (§53 advisor framing — prestige bet, not a transit backbone, mirroring Hyperloop).** Attempting to construct the Channel Tunnel surfaces a documented advisor warning/flag explicitly naming it a **prestige bet** (not a throughput solution) **before** commitment — the same pre-commitment advisory surface `engine.tunnels.md` AC-9 specifies for Hyperloop, not a post-hoc ticker line. Check: `grep -n "prestige\|advisor" internal/engine/tunnels/channeltunnel*.go` (excluding `_test.go`) finds a pre-construction advisory surface; a passing test asserts the advisory is queryable before the construction command is issued (`grep -rn "func Test.*[Aa]dvisor.*[Cc]hannel\|func Test.*[Pp]restige.*[Cc]hannel" internal/engine/tunnels/*_test.go`). **Dependency note:** the advisor-framing mechanism is `engine.tunnels.md` AC-9's surface, consumed here (ASM-705).
- **AC-8 (§MP/§4 reserved slot — M11-gated, long-horizon build).** The Channel Tunnel is gated at M11 (the reserved future-dev slot) and is a multi-year build: it is unavailable before M11, and its build advances across multiple ticks rather than completing in one. Check: a passing test asserts constructing it before M11 is rejected, and that after a valid start, a single tick does not complete the build (`grep -rn "func Test.*[Pp]reGate.*[Cc]hannel\|func Test.*[Mm]ultiYear.*[Cc]hannel" internal/engine/tunnels/*_test.go`). **False-pass risk:** a one-tick instant build with an M11 label would pass a "gated and exists" read while the "multi-year builds" / reserved-slot character is unmet — the check requires the gate and the multi-tick progression (ASM-705).

### Error handling

- **AC-9 (GR#7).** Constructing the Channel Tunnel without an owned/leased TBM, before the M11 gate, or with a malformed bundling config, produces a registry-sourced error (new `MET-`-range code claimed at build time), never a panic, a silent no-op, or a partially-started bore. Check: `grep -n "MET-" internal/engine/tunnels/channeltunnel*.go` finds a registry-code reference; passing test coverage asserts the returned error's registry code matches AND that no tunnel/bore state was mutated on failure (`grep -rn "func Test.*[Nn]oTBM.*[Cc]hannel\|func Test.*[Pp]reGate.*[Cc]hannel" internal/engine/tunnels/*_test.go`).
- **AC-10 (GR#7).** A malformed or schema-invalid `data/channeltunnel.json` (a missing capex figure, a negative length, an unrecognised bundle key) produces a registry-sourced load-time error distinct from AC-9's, never a silent default substitution. Check: `grep -n "MET-" internal/engine/tunnels/channeltunnel*.go` finds a second distinct code; passing test coverage (`grep -rn "func Test.*[Mm]alformed.*[Cc]hannel\|func Test.*[Ii]nvalidChanneltunnel" internal/engine/tunnels/*_test.go`) asserts the error's registry code matches AND that no default-substituted figure was loaded.

### ASM-689 — TBM/orders consume same-package TunnelsAPI; no channeltunnel→tunnels/build edge (amends AC-2/AC-3)
