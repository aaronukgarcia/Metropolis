# System Prompt: Metropolis Macroeconomics & Wage Engine

## 1. Core Economic Directives
You are tasked with building the economic engine for a Metropolis simulation game. The economy is closed and tightly controlled. **Do not create random jobs on the fly.** Every job must trace back to a predefined occupation matrix, triggered strictly by building construction. 

Citizens and the city itself operate on a cash-only basis (no debt). Only the **Player** can utilize debt, borrowing at standard LIBOR rates until the debt service exceeds revenue.

## 2. The Generosity Slider & Wage Mathematics
The global standard of living is controlled by a central `Generosity` state variable, $G$, where $G \in [-5, 5]$. Baseline market rate is $0$.

The annual salary for any occupation is calculated using the following formula:
$$S_{final} = S_{base} \times R_{occ} \times (1 + \alpha G)$$
*   $S_{base}$ = Global Baseline Salary (e.g., 50,000)
*   $R_{occ}$ = Occupation-specific multiplier
*   $\alpha$ = Scaling factor per point of Generosity (e.g., 0.1 for a 10% swing per point)

## 3. The Occupation Matrix
Implement a static lookup table that strictly defines the $R_{occ}$ (multiplier) for every job class. Jobs only spawn when their parent building is completed. 

*   **Tier 1: Unskilled / Baseline**
    *   Factory Worker ($R_{occ} = 0.6$): Spawned by `Factory`
    *   Retail Clerk ($R_{occ} = 0.5$): Spawned by `Commercial Zone`
*   **Tier 2: Essential Civic (The Peg)**
    *   Fireman ($R_{occ} = 1.0$): Spawned by `Firestation`
    *   Nurse ($R_{occ} = 1.0$): Spawned by `Hospital`
    *   Teacher ($R_{occ} = 1.0$): Spawned by `School`
*   **Tier 3: Professionals**
    *   Doctor ($R_{occ} = 2.0$): Spawned by `Hospital`
    *   Engineer ($R_{occ} = 1.8$): Spawned by `Power Plant`
*   **Tier 4: Experts**
    *   Expert Scientist ($R_{occ} = 3.0$): Spawned by `Fab Lab`

## 4. Job Demand & M1 Liquidity
*   **Demand UI:** When a user queues a building (e.g., a Hospital), the UI must instantly calculate and display the labor demand at current slider rates. (e.g., *"Demand: 10 Doctors @ 100,000/yr, 30 Nurses @ 50,000/yr"*).
*   **M1 Money Supply:** The game must constantly calculate and display the M1 (Total liquid currency in the system). M1 increases via Player actions/exports and decreases via Player debt servicing. Salaries distribute the M1 but do not create it.
*   **Player Debt Limit:** Calculate player borrowing capacity dynamically. If `Interest Payments > (Tax Revenue - Civic Upkeep)`, trigger a debt default state.
